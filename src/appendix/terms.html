부록

용어 풀이

본문에서 정의한 용어를 모았습니다. 정의는 본문에서 처음 정의한 뜻을 따릅니다.

정렬 기준: 한국어 용어는 가나다순, 영어 용어와 파일 이름은 알파벳순입니다.

한국어 용어

결정 기록
결정마다 번호, 날짜, 결정 내용, 대체 관계, 이유를 남기는 문서입니다.
권한 규칙(Permission Rule)
Claude Code에서 도구 사용을 허용(allow), 확인 요청(ask), 금지(deny)하는 규칙입니다. deny, ask, allow 순서로 평가합니다.
권한 모드(Permission Mode)
Claude Code에서 권한 규칙에 일치하지 않는 동작을 처리하는 방식입니다.
규칙 문서
에이전트가 세션마다 읽는 프로젝트 지침입니다. CLAUDE.md와 AGENTS.md가 해당합니다.
대규모 언어 모델(Large Language Model, LLM)
입력된 토큰을 바탕으로 다음 토큰을 예측해 결과를 생성하는 모델입니다.
독립 검수
결과를 만들지 않은 다른 에이전트나 사람이 결과를 검토하는 검증 방법입니다.
샌드박스(Sandbox)
명령이 접근할 수 있는 파일 시스템과 네트워크를 운영 체제 수준에서 제한하는 격리 환경입니다.
수용 기준
결과물이 받아들여지기 위해 충족해야 하는 조건입니다.
승인 정책(Approval Policy)
Codex가 동작 전에 멈추고 사용자에게 확인하는 시점을 정하는 설정입니다.
에이전트(Agent)
모델이 반복 루프 안에서 스스로 도구를 사용하는 시스템입니다.
완료 기준
결과를 받아들이기 위해 충족해야 하는 조건입니다. 작업을 맡기기 전에 검사할 수 있는 형태로 작성합니다.
인계 메모
작업을 다른 세션이나 에이전트에 넘길 때 현재 상태, 읽을 문서, 미결정 사항, 다음 작업을 정리한 문서입니다.
자동 메모리
Claude Code가 작업 중의 수정 요청과 선호를 스스로 기록하고 다음 세션에 읽는 기능입니다.
작업 단위
한 세션 안에 끝나고 완료 여부를 확인할 수 있는 크기로 나눈 작업입니다.
진행 기록
작업 단위별 상태와 다음 작업을 남기는 기록입니다.
컨텍스트(Context)
모델이 응답을 생성할 때 입력되는 정보 전체입니다. 프롬프트는 그 일부입니다.
컨텍스트 엔지니어링(Context Engineering)
모델이 응답을 생성하는 동안 필요한 정보를 선별하고 유지하는 전략입니다.
컨텍스트 윈도(Context Window)
모델이 한 번에 처리할 수 있는 토큰의 범위입니다.
토큰(Token)
모델이 글을 처리하는 최소 단위입니다.
풀 리퀘스트(Pull Request)
코드 변경을 저장소에 반영하기 전에 검토를 요청하는 단위입니다.
프롬프트 엔지니어링(Prompt Engineering)
원하는 결과를 얻도록 모델에 주는 지시문을 작성하고 구성하는 방법입니다.
하네스(Harness)
모델 바깥에서 에이전트가 일하는 환경을 이루는 장치 전체입니다. 이 책은 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소로 나눕니다.
하네스 엔지니어링(Harness Engineering)
에이전트가 신뢰할 수 있는 결과를 내도록 모델 바깥의 작업 환경을 설계하는 일입니다.
하위 에이전트(Subagent)
Claude Code에서 특정 작업을 맡도록 별도로 정의한 에이전트입니다.
훅(Hook)
정해진 시점에 자동으로 실행되는 셸 명령입니다. 에이전트의 판단과 관계없이 적용됩니다.

영어 용어와 파일 이름

AGENTS.md
Codex가 작업 전에 읽는 규칙 문서 파일입니다. Claude Code는 CLAUDE.md가 없을 때 이 파일을 읽습니다.
CI(Continuous Integration)
저장소에 변경을 반영할 때마다 빌드와 검사를 자동으로 실행하는 방식입니다.
CLAUDE.md
Claude Code가 세션마다 읽는 규칙 문서 파일입니다.
lint
원고나 코드의 형식 오류를 정해진 규칙으로 자동 검사하는 도구입니다.
MCP(Model Context Protocol)
외부 시스템의 기능을 에이전트의 도구로 연결하는 규약입니다. 이를 구현한 서버를 MCP 서버라고 합니다.
Skill
필요할 때만 읽히는 지침과 자료의 묶음입니다.
