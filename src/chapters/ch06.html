Chapter 6 검증 설계: 완료 보고 대신 증거 받기

에이전트는 작업을 마치면 완료 보고를 작성하며, 그 보고는 에이전트 자신의 판단입니다. 결과를 받아들이는 근거는 완료 보고가 아니라, 검사 출력과 산출물처럼 관리자가 직접 확인할 수 있는 증거입니다. 그래서 완료 보고만으로 결과를 받아들이면, 실제로 동작하지 않는 결과가 완료로 처리됩니다. 따라서 관리자는 작업을 맡기기 전에 어떤 증거로 완료를 판정할지 정해야 합니다. 이 장에서는 완료 기준을 검사로 변환하는 방법과 검증 방법의 선택 기준을 다룹니다.

  • 완료 보고는 결과를 만든 쪽의 판단이므로 판정 근거가 아닙니다.
  • 검증 방법은 자동 검사, 출력 확인, 독립 검수의 세 가지입니다.
  • 완료 기준은 작업을 맡기기 전에 검사 가능한 형태로 작성합니다.

완료 보고가 근거가 되지 않는 이유

Anthropic은 장시간 실행 에이전트 실험에서 에이전트가 충분한 시험 없이 기능을 완료로 표시하는 실패를 보고했습니다. 에이전트는 코드를 수정하고 단위 테스트까지 실행했지만, 기능이 처음부터 끝까지 동작하지 않는다는 사실은 인식하지 못했습니다. 브라우저 자동화 도구로 사람이 사용하는 방식 그대로 시험하도록 지시하자, 에이전트는 코드만으로는 드러나지 않던 오류를 발견하고 수정했습니다(Young, 2025).

이 사례는 두 가지를 보여 줍니다. 결과를 만든 에이전트의 판단은 완료의 근거가 되지 않습니다. 확인 수단을 제공하면 에이전트도 오류를 발견합니다.

이 책의 작가는 에이전트의 완료 보고 대신 검사 명령의 출력 원문을 근거로 받습니다. 원고를 수정했다는 보고에는 빌드, lint, 사이트 검증 명령의 출력이 함께 있어야 합니다. 저장소에 반영된 뒤에는 GitHub Actions의 검사 결과로 다시 확인합니다.

검증 방법의 선택

검증 방법은 세 가지입니다. 자동 검사는 스크립트나 테스트가 결과를 판정합니다. 출력 확인은 관리자가 명령의 출력이나 산출물을 직접 확인합니다. 독립 검수는 결과를 만들지 않은 다른 에이전트나 사람이 검토합니다. 그림 6-1은 작업에서 판정까지의 흐름을, 표 6-1은 방법별 적합한 대상을 보여 줍니다.

OpenAI는 Codex로 제품을 개발하면서 문서 구조를 전용 lint와 CI로 기계적으로 검사했다고 밝혔습니다. 사람은 작업의 우선순위를 정하고 결과를 검증하는 역할을 맡았습니다(Lopopolo, 2026). 반복되는 확인은 자동 검사로 옮기고, 사람은 판단이 필요한 확인에 시간을 사용하는 구성입니다.

완료 기준을 검사로 변환

완료 기준이 문장으로만 있으면 판정하는 사람마다 결과가 달라집니다. 완료 기준은 작업을 맡기기 전에 검사할 수 있는 형태로 작성합니다. 표 6-2는 문장으로 작성된 완료 기준을 검사로 변환한 예입니다.

수치 대조 검사 예제

Chapter 1의 주간 보고서 예제는 검증 단계로 수치 대조 검사를 사용합니다. 검사 스크립트 verify_counts.py는 보고서에 적힌 완료 건수, 작업 목록, 미해결 이슈를 원본 CSV 자료와 대조합니다. 다음은 스크립트의 판정 부분입니다.

m = re.search(r"이번 주 완료\s*(\d+)\s*건", text)
stated = int(m.group(1)) if m else None
print(f"원본 완료 작업 {len(done)}건: {', '.join(done)}")
print(f"보고서에 적힌 완료 건수: {stated if stated is not None else '없음'}")
if stated != len(done):
    errors.append(f"완료 건수 불일치(보고서 {stated}, 원본 {len(done)})")

스크립트는 판정 근거인 원본 건수와 보고서 건수를 함께 출력합니다. 관리자는 "검증을 통과했다"는 보고가 아니라, 두 수치가 출력된 원문을 확인합니다. 검사 스크립트는 권한 설정으로 수정을 금지해서, 에이전트가 판정 기준을 변경하지 못하게 합니다.

에이전트가 스스로 확인했다고 보고하면 충분하다는 의견이 있습니다. 앞의 Anthropic 사례에서 에이전트는 단위 테스트를 실행하고도 기능이 동작하지 않는 사실을 인식하지 못했습니다. 확인을 했다는 보고와 확인의 결과는 다른 정보입니다.

검증 설계는 작업을 맡기기 전에 완료 기준을 검사로 변환하고, 그 출력 원문을 판정의 근거로 정하는 일입니다.
