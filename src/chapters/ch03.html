Chapter 3 하네스로 에이전트 설계하기

에이전트(Agent)는 맡길 업무가 하네스(Harness)의 설정으로 옮겨져야 동작합니다. 에이전트의 동작을 정하는 것은 요청 문장이 아니라, 목적부터 승인 지점까지 하네스에 정해 둔 항목입니다. 그래서 항목 하나가 비어 있으면 그 부분은 모델의 추측이나 제품의 기본값으로 채워집니다. 따라서 관리자는 에이전트를 만들기 전에 명세서로 항목을 모두 정해야 합니다. 이 장에서는 에이전트 명세서를 작성하고, 주간 보고서 에이전트를 설계해 제품 파일로 옮기는 방법을 다룹니다.

  • 에이전트 명세서는 목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점의 아홉 항목입니다.
  • 같은 요청도 프롬프트, 컨텍스트, 하네스의 순서로 설계할수록 결과가 실제 업무에 가까워집니다.
  • 명세서의 항목은 규칙 문서, 권한 설정, 검사 스크립트 같은 제품 파일로 옮깁니다.

에이전트 명세서

에이전트 명세서는 맡길 업무를 하네스의 설정으로 옮기기 전에 정할 항목의 목록입니다. 명세서는 아홉 항목으로 구성합니다. 그림 3-1은 아홉 항목을, 표 3-1은 항목별로 정할 내용과 자세히 다루는 장을 보여 줍니다.

종료 조건은 명세서에서 누락되기 쉬운 항목입니다. Agent SDK 문서는 상한이 없으면 열린 요청에서 루프가 오래 실행될 수 있다고 설명합니다(Anthropic, 2026). 명세서의 각 항목은 다음 절의 예제처럼 업무 한 건에 적용해 채웁니다.

주간 보고서 에이전트: 같은 요청, 세 층의 개선

이 절은 명세서의 항목을 주간 보고서 에이전트에 적용합니다.

같은 모델에 같은 업무를 맡겨도, 어느 층까지 설계했는지에 따라 결과가 달라집니다. 아래 예제는 가상 프로젝트인 경비 정산 시스템 개편의 주간 보고서 초안 작성을 프롬프트, 컨텍스트(Context), 하네스의 순서로 개선합니다.

프롬프트만 설계한 경우

첫 단계는 요청 문장만 다듬는 것입니다.

이번 주 프로젝트 주간 보고서 초안을 작성해 줘.
진행 현황, 이슈, 다음 주 계획의 세 절로 나눠 줘.
진행 현황은 작업명, 담당자, 진행률 열이 있는 표로 정리해 줘.

예상 결과: 절 구성과 표 형식은 요청과 일치합니다. 작업명과 진행률은 실제 프로젝트와 무관한 예시 값으로 채워집니다. 모델은 이번 주에 실제로 진행된 작업을 알지 못하기 때문입니다.

컨텍스트를 설계한 경우

두 번째 단계는 보고서에 필요한 자료를 함께 제공하는 것입니다.

아래 자료로 이번 주 프로젝트 주간 보고서 초안을 작성해 줘.
절 구성과 표 형식은 지난주 보고서를 따라 줘.
자료에 없는 내용은 작성하지 말고 "확인 필요"로 표시해 줘.

<지난주 보고서>
(지난주 보고서 전문)
</지난주 보고서>
<이번 주 완료 작업>
(작업 관리 도구에서 내려받은 목록)
</이번 주 완료 작업>
<미해결 이슈>
(이슈 관리 도구에서 내려받은 목록)
</미해결 이슈>

예상 결과: 실제 작업과 이슈가 보고서에 반영되고, 형식은 지난주 보고서와 일치합니다. 자료가 없는 항목은 "확인 필요"로 표시됩니다.

이 단계에도 두 가지 한계가 남습니다. 매주 사람이 자료를 모아 붙여 넣어야 합니다. 보고서의 수치가 원본 자료와 일치하는지 확인하는 절차도 없습니다.

하네스를 설계한 경우

세 번째 단계는 에이전트가 일하는 환경을 정하는 것입니다. 표 3-2는 다섯 구성 요소를 이 예제에 적용한 설정입니다.

예상 결과: 사람이 자료를 모으지 않아도 실제 작업이 반영된 초안이 생성됩니다. 수치가 원본과 다르면 발송 전 검증 단계에서 드러납니다. PM은 초안 검토와 발송 승인에만 시간을 사용합니다.

세 단계 모두 같은 모델을 사용합니다. 결과의 차이는 모델이 아니라 어느 층까지 설계했는지에서 나옵니다.

제품 파일로 옮기기

앞 절의 주간 보고서 에이전트는 Claude Code 파일로 구현되어 있습니다. 실행 자료는 저장소의 examples/ch01-01/ 폴더에 있습니다. 표 3-3은 표 3-2의 설정이 어느 파일에 구현되었는지 보여 줍니다.

다음은 권한 설정 파일의 내용입니다. 원본 자료와 검사 스크립트, 규칙 문서의 수정을 금지해서, 에이전트가 검증 기준 자체를 변경하지 못하게 합니다.

{
  "permissions": {
    "allow": [
      "Read(./data/**)",
      "Read(./output/**)",
      "Edit(./output/**)",
      "Bash(python verify_counts.py)",
      "Bash(python3 verify_counts.py)"
    ],
    "deny": [
      "Edit(./data/**)",
      "Edit(./verify_counts.py)",
      "Edit(./CLAUDE.md)",
      "Edit(./.claude/**)",
      "WebFetch",
      "WebSearch"
    ]
  }
}

에이전트 설계는 명세서의 아홉 항목을 정하고, 각 항목을 하네스의 설정으로 옮기는 일입니다.
