부록

용어 풀이

본문에서 정의한 용어를 모았습니다. 정의는 본문에서 처음 정의한 뜻을 따르고, 괄호 안의 장 링크로 본문의 설명을 찾아갈 수 있습니다.

정렬 기준: 한국어 용어는 가나다순, 영어 용어와 파일 이름은 알파벳순입니다.

한국어 용어

검사 스크립트
단위 테스트와 수용 시험을 한 번에 실행하는 파일입니다. 이 책의 예제에서는 check.py입니다. (Chapter 3)
격리
접근 범위를 운영 체제 수준에서, 곧 에이전트 프로그램이 아니라 컴퓨터의 운영 체제가 막는 방식으로 제한하는 일입니다. 샌드박스와 격리된 실행 환경(컨테이너나 가상 머신)이 해당합니다. (Chapter 9)
결정 기록
결정마다 번호, 날짜, 결정 내용, 대체 관계, 이유를 남기는 문서입니다. 이 책의 저장소에서는 DECISIONS.md입니다. (Chapter 8)
결합형
작업 순서와 승인 지점은 워크플로처럼 미리 정하고, 각 단계 안의 작업은 에이전트가 판단하는 형태입니다. 워크플로는 순서를 모두 코드로 정하고, 에이전트는 순서까지 모델이 정하며, 결합형은 그 중간입니다. (Chapter 1)
권한 규칙(Permission Rule)
Claude Code에서 도구 사용을 허용(allow), 확인 요청(ask), 금지(deny)하는 규칙입니다. 금지, 확인 요청, 허용의 순서로 평가합니다. (Chapter 2)
권한 모드(Permission Mode)
Claude Code에서 어느 권한 규칙에도 일치하지 않는 요청을 물어볼지, 허용할지, 거부할지 정하는 설정입니다. 예를 들어 default는 파일 수정과 명령 실행 대부분을 실행 전에 묻고, plan은 읽고 계획만 작성합니다. (Chapter 10)
규칙 문서
에이전트가 세션마다 읽는 프로젝트 지침입니다. CLAUDE.md와 AGENTS.md가 해당합니다. (Chapter 5)
대규모 언어 모델(Large Language Model, LLM)
입력된 토큰을 바탕으로 다음 토큰을 예측해 결과를 생성하는 모델입니다. (Chapter 1)
도구
파일 읽기, 명령 실행, 검색처럼 모델 바깥에서 실행되는 기능입니다. (Chapter 1)
도구 호출
모델이 특정 도구를 정해진 입력으로 실행해 달라고 요청하는 것입니다. (Chapter 1)
독립 검수
결과를 만들지 않은 다른 에이전트나 사람이 결과를 검토하는 검증 방법입니다. (Chapter 7)
샌드박스(Sandbox)
셸 명령(터미널에서 실행하는 명령)과 그 하위 프로세스가 접근할 수 있는 파일과 네트워크를 운영 체제 수준에서 제한하는 장치입니다. Claude Code에서는 기본으로 꺼져 있고, 파일 편집 도구는 대상이 아닙니다. (Chapter 9)
세션
에이전트와 한 번 대화를 시작해 끝낼 때까지입니다. 새 세션은 이전 세션의 대화를 알지 못합니다. (Chapter 8)
수용 기준
사람이 정한 완료 조건으로, 결과물이 받아들여지기 위해 충족해야 하는 조건입니다. 변경 요청 문서에 적습니다. (Chapter 3)
수용 시험
수용 기준을 충족하는지 확인하는 시험입니다. 이 책의 예제에서는 acceptance/ 폴더의 시험입니다. (Chapter 3)
승인 정책(Approval Policy)
OpenAI의 에이전트 도구인 Codex가 동작 전에 멈추고 사용자에게 확인하는 시점을 정하는 설정입니다. 동작을 금지하지는 않으며, 금지는 규칙 파일이 맡습니다. (Chapter 10)
승인 지점
되돌리기 어려운 동작에서 사람이 개입하는 자리입니다. 사람이 승인하거나 거절하는 확인 요청과, 사람이 직접 하는 금지로 둡니다. (Chapter 9)
실패 기록
실패와 원인 구성 요소, 추가한 장치를 적은 문서입니다. 같은 종류가 다시 나온 실패와 위험이 큰 실패를 올립니다. 이 책의 저장소에서는 FAILURES.md입니다. (Chapter 11)
실행 로그
하네스가 남기거나, 설정하면 남는 실행 기록입니다. 세션 기록, 실행 결과, 훅 기록, 조직 지표(조직의 설정으로 켜서 모으는 사용 지표)가 해당합니다. (Chapter 8)
에이전트 명세서
에이전트를 설계할 때 정하는 아홉 항목(목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점)입니다. (Chapter 3)
에이전트(Agent)
모델이 루프(작업을 반복하는 실행 흐름) 안에서 도구를 사용해 다음 행동을 스스로 정하고, 결과를 확인하며, 목표를 이룰 때까지 반복하는 시스템입니다. 모델과 하네스로 이루어집니다. (Chapter 1)
완료 기준
요청 한 건이나 작업 단위 하나가 받아들여지기 위해 충족해야 하는 조건입니다. 요청의 네 요소 가운데 하나이며, 작업 단위 목록에서는 작업을 맡기기 전에 검사할 수 있는 형태로 변환합니다. 사람이 정한 결과물 전체의 완료 조건인 수용 기준과 달리, 요청이나 작업 단위마다 적습니다. (Chapter 4) (Chapter 7)
워크플로(Workflow)
미리 정한 코드 경로에 따라 모델과 도구를 조율하는 시스템입니다. 다음에 무엇을 할지 모델이 아니라 코드가 정합니다. (Chapter 1)
인계 메모
작업을 다른 세션이나 에이전트에 넘길 때 현재 상태, 읽을 문서, 미결정 사항, 다음 작업, 확인 명령을 정리한 문서입니다. 이 책의 저장소에서는 HANDOFF.md입니다. (Chapter 8)
자동 메모리
Claude Code가 작업 중에 알게 된 내용을 기기 안의 파일에 스스로 기록하고 다음 세션에 읽는 기능입니다. (Chapter 2)
작업 단위
한 세션 안에 끝나고 완료 여부를 확인할 수 있는 크기로 나눈 작업입니다. (Chapter 6)
저장소
파일과 그 변경 이력을 Git으로 관리하는 폴더입니다. 변경을 이력에 남기는 일을 commit이라고 합니다. (부록 실습 1)
지시와 강제
지시는 에이전트가 읽고 따르도록 요청하는 수단(규칙 문서)이고, 강제는 에이전트의 판단과 관계없이 제품이 적용하는 수단(권한 규칙, 훅)입니다. (Chapter 2)
진행 기록
작업 단위별 상태와 다음 작업을 남기는 기록입니다. 이 책의 예제에서는 tasks.json입니다. (Chapter 8)
컨텍스트 엔지니어링(Context Engineering)
모델이 응답을 생성하는 동안 필요한 정보를 선별하고 유지하는 전략입니다. (Chapter 1)
컨텍스트 윈도(Context Window)
모델이 한 번에 처리할 수 있는 토큰의 범위입니다. Claude Code에서는 /context 명령으로 사용 현황을 확인합니다. (Chapter 5)
컨텍스트(Context)
모델이 응답을 생성할 때 입력되는 정보 전체입니다. 프롬프트는 그 일부입니다. (Chapter 1)
토큰(Token)
모델이 텍스트를 나누어 처리하는 단위입니다. Claude Code는 /usage 명령으로 사용량을 확인합니다. (Chapter 1)
풀 리퀘스트(Pull Request)
코드 변경을 저장소에 반영하기 전에 검토를 요청하는 단위입니다. (Chapter 1)
프롬프트
모델에 보내는 요청, 곧 모델에 주는 지시문입니다. (Chapter 1)
프롬프트 엔지니어링(Prompt Engineering)
원하는 결과를 얻도록 모델에 주는 지시문을 작성하고 구성하는 방법입니다. (Chapter 1)
하네스 엔지니어링(Harness Engineering)
에이전트가 신뢰할 수 있는 결과를 내도록 모델 바깥의 작업 환경을 설계하는 일입니다. (Chapter 1)
하네스(Harness)
모델을 에이전트로 동작하게 하는 모델 바깥의 실행 체계입니다. 루프 실행, 도구 제공, 컨텍스트 관리, 권한, 기록, 검증을 맡습니다. 제품이 제공하는 실행 장치(루프, 도구 실행)와 사용자와 팀이 정하는 설정(규칙 문서, 권한 규칙, 훅)으로 나뉩니다. (Chapter 1)
하위 에이전트(Subagent)
Claude Code에서 특정 작업을 맡도록 별도로 정의한 에이전트입니다. (Chapter 2)
훅(Hook)
파일 수정 직후처럼 정해진 시점에 자동으로 실행되는 셸 명령입니다. 예를 들어 파일을 수정할 때마다 테스트를 실행하게 할 수 있으며, 에이전트의 판단과 관계없이 적용됩니다. 제품에는 다른 형식의 훅도 있지만, 이 책은 셸 명령을 실행하는 훅만 다룹니다. (Chapter 2)

영어 용어와 파일 이름

AGENTS.md
Codex가 작업 전에 읽는 규칙 문서 파일입니다. Claude Code는 작업 폴더와 그 위에 CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md가 하나도 없을 때 이 파일을 읽으며, 이 동작의 버전 조건은 Chapter 10의 버전 주석에 있습니다. (Chapter 10)
CI(Continuous Integration)
저장소에 변경을 반영할 때마다 빌드(원고나 코드로 결과물을 만드는 일)와 검사를 자동으로 실행하는 방식입니다. (Chapter 7)
CLAUDE.md
Claude Code가 세션마다 읽는 규칙 문서 파일입니다. (Chapter 5)
lint
원고나 코드의 형식 오류를 정해진 규칙으로 자동 검사하는 도구입니다. (Chapter 7)
MCP(Model Context Protocol)
외부 시스템의 기능을 에이전트의 도구로 연결하는 규약입니다. 이를 구현한 서버를 MCP 서버라고 하며, 사내 시스템이나 외부 서비스를 에이전트가 직접 사용하게 할 때 사용합니다. (Chapter 1)
ReAct
모델이 생각, 행동, 관찰을 번갈아 하며 문제를 푸는 방법으로, 2022년 논문에서 제안되었습니다. (Chapter 1)
Skill
필요할 때만 읽히는 지침과 자료의 묶음입니다. 상시 규칙 문서를 짧게 유지하려고 사용하며, Chapter 11은 Claude Code의 기능 이름 대신 하는 일을 드러내려고 절차 묶음이라고 부릅니다. (Chapter 5)
