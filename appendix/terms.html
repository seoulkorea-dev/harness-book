부록

용어 풀이

본문에서 정의한 용어를 모았습니다. 정의는 본문에서 처음 정의한 뜻을 따릅니다. 괄호 안의 장 링크는 그 용어를 정의하거나 자세히 다룬 곳입니다.

정렬 기준: 한국어 용어는 가나다순, 영어 용어와 파일 이름은 알파벳순입니다.

한국어 용어

검사 스크립트
단위 테스트와 수용 시험을 한 번에 실행하는 파일입니다. 예제에서는 check.py입니다. (Chapter 2) (Chapter 3)
검수 문서
검수한 결과와 수정할 곳을 적은 문서입니다. (마치며)
검증
결과를 받아들이기 전에 확인하는 방법과 기준입니다. 다섯 구성 요소의 하나입니다. (Chapter 1)
검증 기준
수용 기준을 자동으로 판정하는 시험과 그 시험을 실행하는 작은 프로그램(스크립트)을 묶어 이르는 말입니다. 수용 기준은 충족해야 할 조건이고, 검증 기준은 그 조건의 충족 여부를 판정하는 파일입니다. 예제에서는 수용 시험(acceptance/)과 검사 스크립트(check.py)이며, 사람이 작성하고 에이전트의 수정은 금지 규칙으로 막습니다. (Chapter 3)
검토 하위 에이전트
예제에서 바뀐 내용을 수용 기준과 대조해 보고만 하는 하위 에이전트로, 읽기 도구(Read, Grep, Glob)만 사용합니다. (Chapter 3)
격리
접근 범위를 운영 체제 수준에서, 곧 에이전트 프로그램이 아니라 컴퓨터의 운영 체제가 막는 방식으로 제한하는 일입니다. 샌드박스와 격리된 실행 환경(컨테이너나 가상 머신)이 해당합니다. (Chapter 9)
결정 기록
무엇을 왜 정했는지 남긴 기록으로, 결정마다 번호, 날짜, 결정 내용, 대체 관계, 이유를 남기는 문서입니다. 예제와 책 저장소에서는 DECISIONS.md입니다. (Chapter 1) (Chapter 8)
결합형
작업 순서와 승인 지점은 워크플로처럼 미리 정하고, 각 단계 안의 작업은 에이전트가 판단하는 형태입니다. 워크플로는 순서를 모두 코드로 정하고, 에이전트는 순서까지 모델이 정하며, 결합형은 그 중간입니다. (Chapter 1)
구현 에이전트
예제에서 작업 단위를 처리하며 코드를 수정하는 주 에이전트입니다. (Chapter 3)
권한 규칙(Permission Rule)
Claude Code에서 도구 사용을 허용(allow), 확인 요청(ask), 금지(deny)하는 규칙입니다. 금지, 확인 요청, 허용의 순서로 평가합니다. (Chapter 1) (Chapter 2)
권한 모드(Permission Mode)
Claude Code에서 도구 호출을 승인하는 방식을 정하는 설정으로, 어느 권한 규칙에도 일치하지 않는 요청을 물어볼지, 허용할지, 거부할지가 모드에 따라 달라집니다. 예를 들어 default(수동 모드)는 파일 수정, 셸 명령, 네트워크 접근 대부분을 실행 전에 묻고, plan은 읽고 계획만 작성하며, auto는 사람 대신 분류기 모델이 실행 전에 동작을 검토합니다. (Chapter 1) (Chapter 10)
권한 설정
권한 규칙을 적는 설정 파일입니다. Claude Code의 프로젝트에서는 권한 규칙과 훅을 담는 .claude/settings.json이며, 하네스 설정 파일의 하나입니다. (Chapter 1) (Chapter 3)
규칙 문서
에이전트가 세션마다 읽는 프로젝트 지침입니다. CLAUDE.md와 AGENTS.md가 해당합니다. (Chapter 1) (Chapter 5)
규칙 파일
Codex에서 명령의 실행을 제품이 강제하는 파일입니다. 실행 거부(forbidden)로 적은 규칙은 확인 없이 명령을 거부하며, 에이전트가 읽고 따르는 지시인 규칙 문서와 다릅니다. (Chapter 10)
기록
설정에서 정하는 구성 요소로, 무엇을 왜 정했는지 남긴 결정 기록과 작업이 어디까지 진행되었는지 남긴 진행 기록입니다. 실행 장치의 세션 기록과는 대상이 다릅니다. Chapter 8은 여기에 규칙 문서를 더해 기록을 세 종류로 나눕니다. (Chapter 1) (Chapter 8)
기준표
채점할 때 항목마다 무엇을 보고 어떻게 판정할지 적은 표입니다. (Chapter 7)
다섯 구성 요소
설정에서 정하는 항목을 다섯으로 정리한 것으로, 역할, 도구, 권한, 기록, 검증입니다. (Chapter 1)
단위 테스트
프로그램의 부품 하나가 정해진 대로 동작하는지 확인하는 시험입니다. 예제에서는 tests/ 폴더에 있으며, 사람이 작성하는 수용 시험과 달리 구현 에이전트가 수정할 수 있습니다. (Chapter 2)
대규모 언어 모델(Large Language Model, LLM)
입력된 토큰을 바탕으로 다음 토큰을 예측해 결과를 생성하는 모델입니다. (Chapter 1)
도구
파일 읽기, 명령 실행, 검색처럼 모델 바깥에서 실행되는 기능입니다. (Chapter 1)
도구 호출
모델이 특정 도구를 정해진 입력으로 실행해 달라고 요청하는 것입니다. (Chapter 1)
독립 검수
결과를 만들지 않은 다른 에이전트나 사람이 결과를 검토하는 검증 방법입니다. (Chapter 7)
변경 요청 사항
운영 중인 시스템의 기능을 어떻게 변경할지 요청한 내용입니다. 예제의 경비 정산 시스템 개편 변경 요청 사항은 정산 요청 화면에 프로젝트 코드 선택 항목을 추가해 달라는 가상 회사 재무팀의 요청이며, 변경 요청 사항 문서(docs/CR.md)에 적습니다. (Chapter 1)
변환
완료 기준을 통과나 실패로 가르는 검사로 만드는 일입니다. (Chapter 7)
빌드
원고나 코드로 결과물을 만드는 일입니다. (Chapter 7)
상시 규칙
에이전트가 읽는 정보 가운데 모든 작업에 해당하는 규칙으로, 세션이 시작될 때마다 규칙 문서에서 들어옵니다. (Chapter 5)
샌드박스(Sandbox)
셸 명령(터미널에서 실행하는 명령)과 그 하위 프로세스가 접근할 수 있는 파일과 네트워크를 운영 체제 수준에서 제한하는 장치입니다. Claude Code에서는 기본으로 꺼져 있고, 파일 편집 도구는 대상이 아닙니다. (Chapter 1) (Chapter 9)
설정
하네스 가운데 사용자와 팀이 맡길 업무에 맞춰 정하는 층입니다. 규칙 문서, 권한 설정, 자동 검사, 역할 분담처럼 정하는 값이며, 설정이 없어도 에이전트는 제품의 기본값으로 동작합니다. 정한 값을 제품이 읽는 파일로 옮긴 것이 하네스 설정 파일입니다. (Chapter 1)
세 설계 층
모델 바깥에서 사용자와 팀이 설계하는 프롬프트, 컨텍스트, 하네스를 묶어 이르는 말로, 제품이 정한 기본값 위에서 설계합니다. 세 층은 설계할 때 답할 질문이 다릅니다. 프롬프트는 이번 작업에 무엇을 요청할지, 컨텍스트는 모델에 어떤 정보를 언제 넘길지, 하네스는 무엇을 실행하게 하고 어디까지 허용하며 어떻게 확인할지를 묻습니다. 하네스를 실행 장치와 설정으로 나눈 두 층과는 나누는 기준이 다릅니다. (Chapter 1)
세션
에이전트와 한 번 대화를 시작해 끝낼 때까지입니다. 새 세션은 이전 세션의 대화를 알지 못합니다. (Chapter 1) (Chapter 8)
세션 기록
실행 장치가 세션의 대화를 저장해 나중에 이어 갈 수 있게 남기는 기록입니다. Claude Code는 메시지, 도구 사용, 결과를 로컬 파일에 저장합니다. 다섯 구성 요소의 기록과는 대상이 다릅니다. (Chapter 1) (Chapter 8)
수용 기준
완료 기준 가운데 사람이 업무의 요구로 정한 것으로, 충족해야 할 조건입니다. 예제에서는 변경 요청 사항 문서(docs/CR.md)에 적습니다. (Chapter 1) (Chapter 3)
수용 시험
수용 기준을 충족하는지 확인하는 시험입니다. 사람이 작성하고 에이전트는 수정하지 않으며, 예제에서는 acceptance/ 폴더의 시험입니다. (Chapter 2) (Chapter 3)
승인 정책(Approval Policy)
OpenAI의 에이전트 제품인 Codex가 동작 전에 멈추고 사용자에게 확인하는 시점을 정하는 설정입니다. 동작을 금지하지는 않으며, 금지는 규칙 파일이 맡습니다. (Chapter 10)
승인 지점
되돌리기 어려운 동작에서 사람이 개입하는 자리입니다. 사람이 승인하거나 거절하는 확인 요청과, 사람이 직접 하는 금지로 둡니다. (Chapter 1) (Chapter 3) (Chapter 9)
승인자
사람 가운데 되돌리기 어려운 동작과 작업 단위의 완료를 승인하는 사람입니다. (Chapter 3) (Chapter 6)
시스템 프롬프트
제품이 요청에 미리 포함하는 지시입니다. 이름에 프롬프트가 들어가지만 사람이 입력하는 요청이 아니므로 컨텍스트로 분류합니다. (Chapter 1)
실패 기록
실패와 원인 구성 요소, 추가한 장치를 적은 문서입니다. 같은 종류가 다시 나온 실패와 위험이 큰 실패를 올립니다. 책 저장소에서는 FAILURES.md입니다. (마치며)
실행 로그
하네스가 기본으로 남기거나, 사용자가 설정하면 남는 실행 기록입니다. 세션 기록, 실행 결과, 훅 기록, 조직 지표(환경 변수로 켜서 조직의 관측 시스템으로 보내는 사용 지표)가 해당합니다. (Chapter 8)
실행 장치
하네스 가운데 제품이 제공하는 층입니다. 루프 실행, 도구 제공, 컨텍스트 관리, 권한 확인, 세션 기록처럼 에이전트가 움직이는 데 필요한 기본 기능입니다. (Chapter 1)
압축
대화를 요약해 공간을 확보하는 일입니다. (Chapter 5)
업무 항목
에이전트 명세서의 아홉 항목 가운데 맡기는 업무 자체를 정하는 목적, 입력, 종료 조건, 승인 지점입니다. 나머지 다섯은 다섯 구성 요소인 역할, 도구, 권한, 기록, 검증입니다. (Chapter 3)
에이전트(Agent)
인공지능 모델이 루프(Loop) 안에서 도구를 사용해 다음 행동을 스스로 정하고, 결과를 확인하며, 목표를 이룰 때까지 이 과정을 반복하는 시스템입니다. 루프는 판단, 도구 실행, 결과 확인의 반복입니다. 에이전트는 모델과 하네스로 이루어집니다. (Chapter 1)
에이전트 루프
하네스가 판단과 실행을 반복하는 순서로, 컨텍스트 구성, 판단과 응답, 권한 확인, 도구 실행, 최종 응답의 다섯 단계입니다. 판단과 응답은 모델이, 나머지 단계는 하네스가 맡습니다. 팀이 완료 기준을 정해 두면 최종 응답 앞에 완료 기준 확인이 더해지며, 이 확인에는 단계 번호를 매기지 않습니다. (Chapter 1)
에이전트 명세서
맡길 업무에 필요한 아홉 항목(목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점)과 그 값을 기록한 문서입니다. (Chapter 3)
에이전트 제품
모델을 에이전트로 사용할 수 있게 만든 소프트웨어입니다. OpenAI의 Codex와 Anthropic의 Claude Code가 예입니다. (시작하며)
역할
에이전트가 할 작업과 사람이 할 작업의 경계입니다. 다섯 구성 요소의 하나이며, 주로 규칙 문서에 적습니다. (Chapter 1)
영역
다섯 구성 요소를 모델의 판단을 기준으로 나눈 지시 영역(역할, 기록), 실행 수단 영역(도구), 강제 영역(권한, 검증)입니다. 지시 영역과 실행 수단 영역은 판단의 조건을 정하고, 강제 영역은 판단 결과를 통제합니다. 영역 이름의 지시와 강제는 처리 수단의 이름에서 왔지만, 역할의 일부는 권한 규칙으로 막고 검증의 판정은 사람이 승인하는 것처럼 영역과 처리 수단이 다른 경우가 있습니다. (Chapter 2)
예시 답안
채점하는 쪽이 결과와 비교할, 기준이 되는 답입니다. (Chapter 7)
완료 기준
요청 한 건이나 작업 단위 하나가 끝났다고 판정하는 조건입니다. 요청의 네 요소 가운데 하나이며, 작업 단위 목록에서는 작업을 맡기기 전에 검사할 수 있는 형태로 변환합니다. 완료 기준 가운데 사람이 정한 것이 수용 기준입니다. (Chapter 1) (Chapter 4) (Chapter 7)
외부 실행 환경
파일 시스템, 데이터베이스, 네트워크, 소프트웨어, 기타 외부 서비스처럼 도구가 읽거나 변경하는 대상 전체입니다. 모델과 하네스 바깥에 있으며, 에이전트가 일으키는 변경은 하네스가 실행한 도구를 거칩니다. (Chapter 1)
워크플로(Workflow)
미리 정한 코드 경로에 따라 모델과 도구를 조율하는 시스템입니다. 다음에 무엇을 할지 모델이 아니라 코드가 정합니다. (Chapter 1)
원본 자료
에이전트가 읽기만 하고 변경하면 안 되는 입력 자료입니다. 예제에서는 data/projects.csv입니다. (Chapter 2)
인계 메모
세션을 넘길 때 결정 기록, 진행 기록, 규칙 문서로 알 수 없는 맥락을 현재 상태, 읽을 문서, 미결정 사항, 다음 작업, 확인 명령의 다섯 항목으로 묶어 넘기는 문서입니다. 예제에서는 HANDOFF.md입니다. (Chapter 2) (Chapter 8)
자동 메모리
Claude Code가 작업 중에 알게 된 내용을 기기 안의 파일에 스스로 기록하고 다음 세션에 읽는 기능입니다. (Chapter 8)
작업 단위
한 세션 안에 끝나고 완료 여부를 확인할 수 있는 크기로 나눈 작업입니다. (Chapter 1) (Chapter 6)
작업 단위 목록
작업 단위마다 작업, 완료 기준, 확인 방법, 통과 값을 적은 목록 파일입니다. 진행 기록에 해당하며, 예제에서는 tasks.json입니다. (Chapter 2) (Chapter 6)
작업 단위 분할
맡길 업무를 작업 단위로 나누는 일입니다. (Chapter 6)
작업 입력
이번 작업을 위해 사람이 주는 정보로, 요청과 요청에 첨부하는 자료입니다. 요청할 때마다 들어옵니다. (Chapter 5)
작업 중 생성 정보
작업하면서 에이전트가 얻은 정보로, 에이전트가 열어 모은 파일 내용과 명령이나 도구를 실행해 얻은 출력입니다. (Chapter 5)
장치
검사나 규칙 문서의 한 줄처럼, 같은 실패가 다시 나오지 않도록 구성 요소에 더한 설정입니다. 사용자와 팀이 더하는 설정이므로, 제품이 제공하는 층인 실행 장치와는 다릅니다. (마치며)
저장소
코드와 문서를 변경 이력과 함께 보관하는 곳입니다. (Chapter 1)
종료 코드
명령이 끝나면서 성공이나 실패를 알리려고 돌려주는 숫자입니다. 0은 성공, 0이 아닌 값은 실패를 뜻합니다. (Chapter 2)
주 대화
사람과 에이전트가 주고받는 세션의 대화입니다. 하위 에이전트는 포크를 제외하면 주 대화의 내용을 보지 못합니다. (Chapter 5) (Chapter 6)
주 에이전트
하위 에이전트에게 일을 맡기는 쪽으로, 주 대화에서 사람과 일하는 에이전트입니다. (Chapter 6)
지속적 통합(Continuous Integration, CI)
저장소에 변경이 올라올 때 자동으로 검사를 실행하는 장치입니다. (Chapter 1)
지시와 강제
지시는 에이전트가 읽고 따르도록 요청하는 수단(규칙 문서)이고, 강제는 에이전트의 판단과 관계없이 제품이 적용하는 수단(권한 규칙, 훅)입니다. (Chapter 2)
진행 기록
어떤 작업이 어디까지 진행되었는지 남기는 기록입니다. 예제에서는 tasks.json의 통과 값과 작업 단위별 commit입니다. (Chapter 1) (Chapter 8)
채점
기준 하나를 정답, 오답이나 점수 같은 판정값으로 만드는 일입니다. 방법은 코드 기반, 대규모 언어 모델 기반, 사람의 세 가지입니다. (Chapter 7)
컨텍스트(Context)
모델이 응답을 생성할 때 입력되는 정보 전체입니다. 프롬프트는 그 일부입니다. (Chapter 1)
컨텍스트 엔지니어링(Context Engineering)
모델이 응답을 생성하는 동안 필요한 정보를 선별하고 유지하는 전략입니다. (Chapter 1)
컨텍스트 윈도(Context Window)
모델이 한 번에 처리할 수 있는 토큰의 범위입니다. (Chapter 1)
코딩 에이전트
저장소의 코드를 읽고 수정하며 테스트를 실행하는 에이전트 제품입니다. Claude Code와 Codex가 예입니다. (Chapter 1)
턴
에이전트 루프에서 세는 단위로, 문서마다 범위가 다릅니다. Agent SDK 문서는 도구 호출을 주고받는 왕복 한 번을, Claude Code 용어집과 Codex의 에이전트 루프 글은 사용자 입력 하나에서 응답이 끝날 때까지를 한 턴이라고 합니다. 사용할 때는 어느 문서 기준인지 밝힙니다. (Chapter 1)
토큰(Token)
모델이 텍스트를 나누어 처리하는 단위입니다. (Chapter 1)
통과 값
작업 단위 목록에서 단위가 끝났는지를 적는 칸입니다. 새로 등록한 미완료 단위는 false이고, 완료를 확인한 단위는 true입니다. (Chapter 2) (Chapter 6)
편집 뒤 훅
파일을 편집할 때마다 검사를 실행하도록 설정한 PostToolUse 훅(도구 실행 뒤에 실행되는 훅)입니다. 이미 실행된 편집은 되돌리지 못하고, 종료 코드 2로 끝나면 오류 출력을 모델에 전달합니다. (Chapter 2)
풀 리퀘스트(Pull Request)
코드 변경을 저장소에 반영하기 전에 검토를 요청하는 단위입니다. (Chapter 1)
프롬프트
사람이 이번 작업에 입력하는 요청입니다. 컨텍스트의 일부이며, 제품이 미리 포함하는 시스템 프롬프트는 컨텍스트로 분류합니다. (Chapter 1)
프롬프트 엔지니어링(Prompt Engineering)
원하는 결과를 얻도록 모델에 주는 지시문을 작성하고 구성하는 방법입니다. (Chapter 1)
필요할 때 읽는 문서
위치와 읽힐 조건만 안내해 두고 필요할 때 읽는 세부 지침과 자료입니다. 규칙 문서에 위치를 안내한 세부 설계 문서, Skill, 경로별 규칙, 하위 폴더의 규칙 문서가 해당합니다. (Chapter 5)
하네스(Harness)
모델이 에이전트로 일할 수 있게 하는 모델 바깥의 실행 체계 전체입니다. 제품이 제공하는 실행 장치(루프 실행, 도구 제공, 컨텍스트 관리, 권한 확인, 세션 기록)와 사용자와 팀이 정하는 설정(규칙 문서, 권한 설정, 자동 검사, 역할 분담)으로 나뉩니다. (Chapter 1)
하네스 설정 파일
에이전트 명세서의 값을 옮겨, Claude Code가 정해진 위치에서 자동으로 읽어 들이는 파일입니다. 규칙 문서(CLAUDE.md), 권한 규칙과 훅을 담는 설정 파일(.claude/settings.json), 하위 에이전트 정의가 해당합니다. (Chapter 3)
하네스 엔지니어링(Harness Engineering)
에이전트가 신뢰할 수 있는 결과를 내도록 모델 바깥의 작업 환경을 설계하는 일입니다. (Chapter 1)
하위 에이전트(Subagent)
Claude Code에서 특정 작업을 맡도록 별도로 정의한 에이전트입니다. (Chapter 2)
확인 방법
작업 단위 목록에서 완료 기준을 무엇으로 판정할지 적은 칸으로, 완료 기준을 확인하는 검사나 기록입니다. (Chapter 3) (Chapter 6)
훅(Hook)
파일 수정 직후처럼 정해진 시점에 자동으로 실행되는 셸 명령입니다. 예를 들어 파일을 수정할 때마다 테스트를 실행하게 할 수 있으며, 에이전트의 판단과 관계없이 적용되지만, 훅이 실행되지 않거나 실패하면 막지 못합니다. 제품에는 다른 형식의 훅도 있지만, 본문은 셸 명령을 실행하는 훅만 다룹니다. (Chapter 1) (Chapter 2)

영어 용어와 파일 이름

Agent SDK
Claude Code의 에이전트 루프를 Python이나 TypeScript 프로그램에서 실행하게 하는 라이브러리(Claude Agent SDK)입니다. (Chapter 1)
AGENTS.md
Codex가 작업 전에 읽는 규칙 문서 파일입니다. Claude Code는 작업 폴더와 그 상위 폴더에 CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md가 하나도 없을 때 이 파일을 읽으며, 이 동작의 버전 조건은 Chapter 10의 버전 주석에 있습니다. (Chapter 10)
CLAUDE.md
Claude Code가 세션마다 읽는 규칙 문서 파일입니다. (Chapter 5)
commit
바뀐 파일을 저장소의 기록으로 남기는 명령입니다. (Chapter 3)
commit 확인
사람이 commit을 승인하기 전에 바뀐 파일을 보는 일입니다. (Chapter 3)
lint
원고나 코드의 형식 오류를 정해진 규칙으로 자동 검사하는 도구입니다. (Chapter 7)
MCP(Model Context Protocol)
외부 시스템의 기능을 에이전트의 도구로 연결하는 개방형 표준입니다. 이를 구현한 서버를 MCP 서버라고 하며, 사내 시스템이나 외부 서비스를 에이전트가 직접 사용하게 할 때 사용합니다. (Chapter 1) (Chapter 2)
ReAct
모델이 생각, 행동, 관찰을 번갈아 하며 문제를 푸는 방법으로, 2022년 논문에서 제안되었습니다. (Chapter 1)
Skill
필요할 때 읽히는 지침 묶음입니다. 기본 설정에서는 이름과 설명만 늘 컨텍스트에 있고 본문은 작업에 필요할 때 불러오므로, 상시 규칙 문서를 짧게 유지하는 데 사용합니다. 마치며는 같은 대상을 절차 묶음(Skill)이라고 부릅니다. (Chapter 5) (마치며)
