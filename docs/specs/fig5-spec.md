## 그림 5-1 명세
- 그림 종류: 원리(예제 사실 없음, D-115)
- 목적(결론 제목): 무엇을 언제 컨텍스트에 넣을지 설계해야 합니다
- 부제: 에이전트가 읽는 정보의 네 종류와 컨텍스트 윈도에 들어가는 시점
- 그림이 들어갈 절: kinds
- 형태 후보(시안 두 개): 1. 위에 컨텍스트 윈도 영역(네 종류가 차례로 채우는 가로 막대와 남은 공간, 한도), 아래에 종류별 카드 네 개(들어오는 시점, 출처, 관리 방법). 이 시안은 관계 표의 화살표를 카드의 "언제", "출처" 줄로 대신함 2. 왼쪽에 정보가 오는 곳(규칙 문서, 세부 문서, 사람, 도구 실행) 영역, 오른쪽에 컨텍스트 윈도 영역(위에서 아래로 쌓이는 네 종류와 남은 공간), 둘 사이에 시점 이름이 있는 화살표

### 반드시 보여 줄 것

|---|---|
| 컨텍스트 윈도 | 모델이 한 번에 받는 입력, 한도가 있음 |
| 상시 규칙 | 세션 시작마다, 규칙 문서, 모든 작업에 해당하는 규칙만 짧게 |
| 필요할 때 읽는 문서 | 특정 작업이나 파일을 다룰 때, 세부 문서와 경로별 규칙, 상시 규칙에 위치만 안내 |
| 작업 입력 | 요청할 때마다, 사용자, 필요한 범위로 선별 |
| 작업 중 생성 정보 | 도구 실행마다, 파일 조회와 검사 출력, 도구와 범위로 조절 |
| 남은 공간과 한도 | 한도에 가까워지면 압축 |

## 그림 5-2 명세
- 그림 종류: 원리
- 목적(결론 제목): 자료를 주는 시점을 정하고, 긴 작업은 세 기법으로 관리합니다
- 부제: 미리 제공과 필요할 때 찾기, 컨텍스트 윈도를 넘는 작업의 세 기법
- 그림이 들어갈 절: retrieval
- 형태 후보(시안 두 개): 1. 위 영역 "자료를 주는 두 방법"(카드 두 개 나란히, 가운데 혼합 방식 한 줄), 아래 영역 "긴 작업의 세 기법"(카드 세 개 나란히) 2. 왼쪽 열 두 방법, 오른쪽 열 세 기법을 세로 카드로

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할(research/ch05-sources.md C5-4로 확인, "색인이 오래될 수 있음"은 근거가 간접이라 뺌) |
|---|---|

| 필요할 때 찾기 | 가벼운 식별자만 두고 실행 중 도구로 불러옴, 느리지만 단계적으로 탐색, 탐색 기준이 없으면 컨텍스트 낭비 |

| 구조화된 노트 | 컨텍스트 밖에 노트를 남기고 다시 읽음 |
| 하위 에이전트 | 깨끗한 컨텍스트에서 탐색하고 요약만 돌려줌 |
