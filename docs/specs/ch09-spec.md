## 절 첫 문단(왜 → 무엇 → 어떻게 → 근거)
- 장 첫 문단: 작동(허용된 권한 안에서 파일 수정, 명령 실행) → 한계(그 안에 되돌리기 어려운 동작이 있고, 규칙은 문자열만 대조해 우회될 수 있음) → 결과(원본 자료 손상, 외부 발송, 지출) → 행동(권한 제한, 승인 지점, 접근과 지출의 범위) → 범위(승인, 격리, 비용, CR 적용). 주장 줄 되풀이 삭제
- kinds: 왜(세 경로) → 무엇(이 책의 정리, 셋 모두 허용 범위) → 어떻게(표 9-1: 일반 용어, 수단은 본문에서 설명하는 것만, 샌드박스(Sandbox) 첫 병기) → 각 절 안내
- approval: 왜(되돌리기 어려운 동작은 사람이 먼저 봐야 하지만, 모든 동작에 두면 확인할 일이 많아져 확인이 약해질 수 있음: 이 책의 판단으로 표시) → 무엇(승인 지점: 실행 전에 사람(승인자)이 승인하거나 거절하는 자리, 3장 명세서 항목 상기, 2장 지시와 강제 상기) → 어떻게(세 종류 동작, Anthropic 프롬프트 문서. 되돌릴 수 있는 로컬 동작(파일 수정, 테스트 실행)은 승인 없이) → 기준(확인 요청: 사람이 내용을 보고 진행을 정할 수 있는 동작, 금지: 에이전트가 하지 않고 사람이 직접 하는 동작. 이 책의 정리) → 반론(승인 단계가 많으면 자동화의 의미가 없다)과 답
- permissions: 왜(승인과 금지는 규칙으로 제품이 적용해야 모델의 판단과 관계없이 지켜짐: "Permission rules are enforced by Claude Code, not by the model", S-C9-1) → 무엇(금지(deny), 확인 요청(ask), 허용(allow)과 평가 순서는 2장 도구 노출 범위에서 정함: 한 줄 상기와 링크, 구체성은 순서를 바꾸지 않음) → 어떻게(동작의 위험에 따른 배치, 그림 9-1) → 근거(Anthropic 2026b). 권한 모드는 한 줄(규칙에 없는 요청의 처리, 10장)
- isolation: 왜(Bash 규칙은 명령 문자열만 대조, git -C . push 예, 스크립트를 통한 간접 수정, 보안 경계가 아님) → 무엇(이 책의 정리: 접근 범위를 운영 체제 수준에서 제한하는 격리. 샌드박스는 셸 명령과 그 하위 프로세스의 파일, 네트워크 접근 제한) → 어떻게(권한과 샌드박스의 역할 분담: 파일 도구는 금지 규칙, 셸과 스크립트는 샌드박스. 샌드박스는 기본 꺼짐, /sandbox로 켬, macOS, Linux, WSL2 지원, 네이티브 Windows 미지원, 모든 확인을 끄는 모드(bypassPermissions)는 인터넷 없는 컨테이너나 가상 머신에서만) → 근거(Anthropic 2026b, c, 프롬프트 주입으로 모델 판단이 뚫려도 샌드박스 제한은 남음). Codex도 승인 정책과 샌드박스의 두 계층(원문 재확인 실패, 기존 기록 근거, 10장 링크)
- cost: 왜(지출도 되돌릴 수 없는 사고이고, 한도에 이르면 사람이 계속 여부를 정하는 멈춤 지점) → 무엇(이 책은 팀이 정할 기준을 세 가지로 정리: 작업 단위(6장), 읽힐 자료(5장, 규칙 문서는 세션마다 읽힘), 지출 한도. 문서의 방법(추적, 한도, 컨텍스트 관리, 모델 선택)과의 대응 한 줄) → 어떻게(그림 9-2) → 근거(Anthropic 2026d). 비용 상한(1장, 실행 한 번)과 지출 한도(팀, 사용자별)의 관계 한 줄. "비용은 토큰에 비례"는 API 과금 기준으로 한정, 구독은 요금제 한도. 확인은 사용량 화면(Claude Code /usage의 Session, 금액은 정가 기준 추정치, 8장 상기)
- example: CR 전체 이름 첫 등장 → 설정 파일(.claude/settings.json, 3장 링크)의 permissions 부분 전체(reference/settings.example.json과 같게) → 읽는 법 한 줄(괄호 안은 대상, *는 무엇이든, **는 아래 모든 폴더) → 표 9-4 CR의 위험 관리(동작, 규칙, 이유): 테스트와 검사 실행, git status, git diff(허용), commit(확인 요청, 반영 시점을 사람이 정함), push(금지, 사람만), data/, acceptance/, check.py, CLAUDE.md, DECISIONS.md, .claude/ 수정(금지, 원본 자료와 검증 기준, 규칙), WebFetch, WebSearch(금지, 외부 자료를 읽지 않음, 3장) → 격리: 예제 설정에는 샌드박스가 없음(기본 꺼짐), 따라서 git -C . push 같은 우회와 스크립트의 간접 수정은 막히지 않으며, 막으려면 /sandbox로 켬(예제 파일은 고치지 않음, Q-053) → 비용: CR은 비용 상한을 두지 않고 한 세션에 끝나는 작업 단위로 다시 실행하는 비용을 줄임(3장, 6장) → 실습 3 링크

## 사실 기준(research/ch09-sources.md)
- 평가 순서, 구체성은 순서를 바꾸지 않음, 규칙은 Claude Code가 강제(S-C9-1)
- Bash 규칙의 문자열 한계: git -C . push 외에도 다른 형태는 불일치, "보안 경계가 아님"(S-C9-1)
- Edit 금지는 파일 도구와 인식되는 셸 파일 명령, 리다이렉션에 적용, 스크립트의 간접 쓰기에는 미적용(S-C9-1)
- 샌드박스: 기본 꺼짐, /sandbox, 지원 OS, 셸 명령(Bash, PowerShell 등)과 자식 프로세스, 파일 도구는 샌드박스 밖(S-C9-3). 버전과 OS 차이는 버전 주석(2026년 10월)
- bypassPermissions: 권한 프롬프트와 안전 확인을 끔, 금지 규칙은 이 모드에서도 적용, 인터넷 없는 컨테이너나 가상 머신에서만(S-C9-2)
- 승인 대상 세 종류는 프롬프트 문서의 예(S-C9-5). 되돌릴 수 있는 로컬 동작은 하도록 권장
- 비용: 비용 문서의 개요(추적, 한도, 컨텍스트 관리, 모델 선택), "비용은 토큰에 비례"는 API 과금, /usage Session은 API 사용자용, 정가 기준 추정치, 지출 한도의 위치(Teams, Enterprise는 조직, 그룹, 개인 단위, Console은 워크스페이스)(S-C9-4). "한도에 이르면 사람이 결정"은 이 책의 설계
- Codex: 승인 정책과 샌드박스의 두 계층(기존 기록, 원문 재확인 실패, 확신 중간). /status는 "남은 컨텍스트 용량" 중심으로 낮추거나 쓰지 않음(S-C9-7)
- 참고 자료: a Prompting best practices, b Configure permissions, c Configure the sandboxed Bash tool, d Manage costs effectively(확인 2026년 10월 20일), OpenAI Agent approvals and security(확인 2026년 10월 4일, 이번 재확인 실패 표기)
