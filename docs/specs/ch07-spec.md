## 절 첫 문단(왜 → 무엇 → 어떻게 → 근거)
- 장 첫 문단: "에이전트는 작업을 마치면 완료 보고를 작성하며, 그 보고는 에이전트 자신의 판단입니다. 그러나 그 판단이 결과가 실제로 동작한다는 뜻은 아닙니다. 그래서 … 완료로 처리됩니다. 따라서 … 정해야 합니다." 범위 문장은 바뀐 절 순서대로(완료 기준의 변환, 검증 방법의 선택, 기준표 채점, CR 적용). 주장 줄 되풀이 문장 삭제
- report: 왜(보고는 일을 한 쪽이 쓴 글, 에이전트는 자기 결과가 틀린 줄 모를 수 있음) → 무엇(이 책은 완료 보고와 증거(검사 출력, 산출물)를 구분) → 근거(Young 2025: 단위 테스트나 curl로 시험하고 끝에서 끝까지 동작하지 않음을 알아차리지 못함, 사람처럼 브라우저 자동화로 시험하게 하자 개선. 단위 테스트는 부품 하나를 확인한다는 한 구절) → 이 책 작가의 방식(출력 원문을 받음, lint와 CI 정의 유지, 빌드 한 구절) → 반론과 답("스스로 확인했다는 보고면 충분하다" → "확인했다는 보고와 확인의 출력은 다른 정보", 보고 문장과 출력 원문의 대비 한 쌍) → 다음 절 연결
- criteria: 왜(증거로 판정하려면 무엇을 확인할지 맡기기 전에 정해져 있어야 함, 문장 기준은 판정자마다 다름) → 무엇(완료 기준은 6장 작업 단위 목록의 칸이고, 수용 기준은 3장에서 사람이 정한 완료 조건이라는 한 줄 상기. 이 책은 완료 기준을 통과, 실패로 갈리는 검사로 바꾸는 일을 변환이라고 정리) → 어떻게("누가 판정해도 같은 결과가 나오는가"로 확인, 빈 출력이 통과인 이유, 응답 코드 200 풀이) → 표 7-1
- methods: 왜(기준을 바꿔도 모두 같은 방법으로 확인할 수 없음) → 무엇(이 책은 확인하는 방법을 누가 판정하는가에 따라 셋으로 정리: 자동 검사는 스크립트와 테스트, 출력 확인은 사용자가 출력과 산출물을 직접, 독립 검수는 결과를 만들지 않은 에이전트나 사람) → 어떻게(기준 항목마다 하나를 고름. 세 층을 모두 거치는 것이 아님. 미통과면 오류 출력을 돌려 같은 단위를 다시 작업(6장 다시 수행 링크)) → 근거(Anthropic Best practices의 "검증할 수단을 주라", "일한 에이전트가 채점하지 않게"(S-C7-6), Lopopolo 2026은 자동 검사 쪽 근거로 연결어와 함께) → 그림 7-1, 표 7-2(해설표), 표 7-3(방법별 적합한 대상)
- rubric: 왜(표 7-1처럼 코드로 바꿀 수 있는 기준만 있지 않음) → 무엇(이 책은 독립 검수의 판정을 채점이라 하고, 채점 방법을 코드 기반, LLM 기반, 사람으로 정리. 검증 방법과의 대응 한 문장: 코드 기반은 자동 검사, LLM 기반과 사람은 독립 검수, 어느 쪽이든 사용자는 판정의 출력 원문을 확인) → 근거(Anthropic 평가 문서, 표 7-4) → 어떻게(기준표와 예시 답안, 판정 형식, 통과 조건, 다른 모델, 그림 7-2와 해설표 7-5) → 정할 것 세 가지(이 책의 정리로 밝힘, "되돌리기 어려운 결정에만 사람"은 6장 선정 기준 링크)
- example: CR 전체 이름 첫 사용, 수용 기준 다섯 가지 상기(3장 링크) → 표 7-6 CR의 기준표 → check.py 발췌(읽기용 표시, 덩어리별 풀이, 정상 출력 한 줄 예) → 검토 하위 에이전트(LLM 기반 채점, 판정 형식 충족/미충족/확인 불가와 근거) → 수정 금지(deny)와 한계(S-C7-4) → 훅으로 강제(S-C7-5, 3장 링크) → 실습 4 안내
