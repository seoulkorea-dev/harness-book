# 그림 6-1, 6-2 명세

## 그림 6-1 명세
- 예제 사실 없음: 그림, 접근성 설명, 캡션에 CR, 작업 번호, 파일 이름, 세션 배치를 넣지 않음(D-116)
- 목적(결론 제목): 업무는 한 세션에 끝나고 확인할 수 있는 작업 단위로 나눠 하나씩 처리합니다
- 부제: 작업 단위 목록과 작업 단위 하나를 처리하는 순서
- 그림이 들어갈 절: split
- 형태 후보(시안 두 개): 1. 위 영역 "작업 단위 목록"(단위마다 적는 네 항목 띠, 담당이 다른 세 종류의 단위 카드), 아래 영역 "작업 단위 하나의 처리 순서"(가로 흐름과 되돌림) 2. 왼쪽 영역 목록(세로 카드), 오른쪽 영역 처리 순서(세로 흐름과 되돌림)

### 반드시 보여 줄 것
| 구성 요소(본문 용어) | 한 줄 역할 |
|---|---|
| 작업 단위 목록 | 단위마다 작업, 완료 기준, 확인 방법, 통과 값(처음은 false)을 적은 파일 |
| 합의가 필요한 단위 | 담당: 사람(승인자). 결과를 결정 기록으로 제공 |
| 확인할 수 있는 단위 | 담당: 에이전트. 검사로 완료 확인 |
| 판단이 필요한 단위 | 담당: 에이전트가 작성, 사람(승인자)이 승인. 통과 값은 사람이 변경 |
| 처리 순서 | 통과 값이 false인 첫 단위 선택 → 수행 → 완료 기준 확인 → 통과 값 true로 갱신 → 다음 단위 |

### 반드시 보여 줄 관계
| 시작 | 끝 | 화살표 이름 | 순서 |
|---|---|---|---|
| 작업 단위 목록 | 첫 단위 선택 | 통과 값이 false인 첫 단위 | 1 |
| 선택 → 수행 → 확인 → 갱신 | 다음 단계 | (주 흐름, 이름 없음 또는 짧게) | 2 |
| 완료 기준 확인 | 수행 | 미달 시 같은 단위 다시(회갈 점선) | 3 |
| 갱신 | 목록 | 다음 단위로 반복(회갈 점선) | 4 |

### 쓰지 않을 것
- 번호 원(1장 체계에서 루프 단계를 뜻함), 제품명, 예제 사실

### 맨 아래 "*" 한 줄

### 해설표 행(표 6-2)
| 구성 요소 | 무엇인가 | 본문의 절 |
|---|---|---|
| 작업 단위 목록 | 단위마다 작업, 완료 기준, 확인 방법, 통과 값 | 예제 절 |
| 담당 | 사람(승인자)이 맡을 단위와 에이전트가 맡을 단위 | 맡길 업무의 선정 |
| 처리 순서 | 통과 값이 false인 첫 단위를 수행하고 완료 기준 확인 뒤 통과 값 갱신 | 이 절 |
| 되돌림 | 미달 시 같은 단위 다시, 갱신 뒤 다음 단위 | 이 절, Chapter 7 |

## 그림 6-2 명세
- 예제 사실 없음(D-116)
- 목적(결론 제목): 작업 단위를 나눠 맡기고 요약만 돌려받습니다
- 부제: 주 에이전트와 하위 에이전트 사이에 오가는 정보와 비용
- 그림이 들어갈 절: multi-agent
- 형태 후보: 1. 왼쪽 주 에이전트 영역, 오른쪽 하위 에이전트 영역(세 카드), 사이에 넘기는 정보(위, 오른쪽 방향)와 돌아오는 요약(아래, 왼쪽 방향), 아래에 비용 띠 2. 위 주 에이전트 영역, 아래 하위 에이전트 세 카드, 아래로 넘기는 정보와 위로 돌아오는 요약

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 주 에이전트 | 작업 단위 배분, 필요한 정보를 요청에 담음, 돌아온 요약을 모아 판단 |
| 하위 에이전트(예: 테스트 실행, 자료 조사, 로그 분석) | 자기 컨텍스트 윈도에서 새 대화로 작업, 주 대화는 보지 않음 |
| 넘기는 정보 | 작업 단위와 필요한 정보 |
| 돌아오는 정보 | 최종 응답(요약)만 |
| 비용 | 하위 에이전트의 지출도 비용 상한에 포함 |

### 쓰지 않을 것
