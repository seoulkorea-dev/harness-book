# Chapter 5 명세

- 장 제목(목차 그대로): 컨텍스트 엔지니어링: 에이전트가 읽는 정보 설계
- 주장 한 줄(유지, src/site.json ch05): 결과를 정하는 것은 요청 문장의 완성도가 아니라, 에이전트가 판단하는 시점에 무엇을 읽고 있는지입니다.
- 할 수 있게 되는 것:
  1. 에이전트가 읽는 정보를 네 종류(상시 규칙, 필요할 때 읽는 문서, 작업 입력, 작업 중 생성 정보)로 나누고 종류마다 관리 방법을 정한다.
  2. 자료를 미리 줄지 필요할 때 찾게 할지 정하고, 긴 작업에 압축, 구조화된 노트, 하위 에이전트를 쓴다.
  3. 규칙 문서를 짧게 쓰고(읽는 순서, 작업 순서, 수정 범위, 중단 규칙, 명령), 같은 실수가 반복될 때 항목을 더한다.

- 4장과 같은 순서: 장 틀 보강, 그림 5-1, 5-2를 1장 기준 시각 체계(FIGURE_STYLE 7절, D-111)로 다시 그림, 그림 5-2 글자 크기 경고 해소, 그림마다 해설표(D-079), v1.1-backlog 5장 항목 처리
- 그림 종류(D-115): 그림 5-1, 5-2 모두 원리 그림. 예제(CR) 사실을 넣지 않고, CR은 새 절 "CR 적용"의 표와 본문이 맡음
- 절과 앵커 유지: resource, kinds, retrieval, rule-doc, maintenance, fail, check, principle, refs(다른 장 링크: ch10 → ch05, 부록 실습 2 → ch05.html#rule-doc). 새 절은 다른 장(ch03, ch04, ch06, ch10)과 같게 id="example", 제목 "예제: CR 에이전트가 읽는 정보", 위치는 원리 절 다음 실패 표 앞(maintenance 다음). 부록 실습 2의 #rule-doc 링크는 유지하고, rule-doc 절에 "예는 아래 예제 절" 안내를 둠(명세 검토 필수 1, 2)
- 첫 문단의 주장 줄 중복 문장을 지움(Q-004, Q-009, Q-018과 같은 처리)
