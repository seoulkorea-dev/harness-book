# 그림 2-2 명세

- 목적(결론 한 문장): 연결한 도구 가운데 권한 규칙을 거친 도구만 작업에 쓰이므로, 도구는 작업에 필요한 만큼만 연결하고 노출합니다.
- 그림이 들어갈 절: 도구 노출 범위(id="tool-scope")
- 형태 후보 두 가지(시안 두 개로 그림):
  1. **왼쪽에서 오른쪽으로 거르는 흐름.** 연결된 도구(내장 도구, 연결한 외부 도구 서버의 도구) → 권한 규칙(금지, 확인, 허용의 평가 순서) → 이 작업에 노출된 도구(읽기 도구, 수정과 실행 도구) 순서로 놓습니다. 금지된 도구는 아래로 빠지는 경고 색 상자로 둡니다. 맨 아래에 하위 에이전트의 최소 도구를 작은 비교 인셋으로 둡니다. 폭은 960입니다.
  2. **도구와 주체의 행렬(CR 기준).** 행은 도구 다섯 가지(파일 읽기와 검색, 파일 수정, 명령 실행, 웹 접근, 외부 도구 서버의 도구)입니다. 열은 연결, 권한 규칙(CR 설정), 구현 에이전트에 노출, 검토 하위 에이전트에 노출입니다. 칸에 "노출", "확인 후 실행", "금지", "이름만"을 적습니다. 금지 칸만 경고 색입니다. 폭은 960입니다.

## 반드시 보여 줄 것
| 구성 요소(본문 용어 그대로) | 한 줄 역할 |
|---|---|
| 연결된 도구 | 하네스에 연결해 에이전트가 쓸 수 있는 도구 전체 |
| 외부 도구 서버의 도구(본문: MCP 서버의 도구) | 이름과 안내만 두고 필요할 때 불러옴 |
| 권한 규칙(금지, 확인, 허용) | 도구 실행 여부를 정함. 금지, 확인, 허용 순서로 평가 |
| 이 작업에 노출된 도구 | 읽기 도구(동시에 실행 가능), 수정과 실행 도구(차례로 실행, 규칙에 따라 확인) |
| 금지된 도구 | 실행되지 않음. 이름만 쓴 금지 규칙은 도구를 목록에서 뺌(조사 확인 뒤 표기) |
| 하위 에이전트 | 맡긴 작업에 필요한 최소 도구만 지정(CR 검토 에이전트: 읽기, 검색 도구 세 개) |
| CR 표시 | 웹 접근은 금지, 테스트와 git 상태 확인은 허용, commit은 확인 |

## 쓰지 않을 것
- 영어 병기(deny, ask, allow → 금지, 확인, 허용). 지금 그림의 영어 표기는 FIGURE_STYLE 5절 위반입니다.
- "MCP"라는 약어를 그림에 쓸지는 **작가 확인**이 필요합니다. 제품명은 아니지만 영어 약어입니다. 대안은 "외부 도구 서버의 도구"입니다.
- 제품명과 회사명, 상자로 감싼 요약, 본문에 없는 분류
