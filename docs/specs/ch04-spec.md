# Chapter 4 명세

- 장 제목: 프롬프트 엔지니어링: 한 번의 요청 설계
- 주장 한 줄: 요청 문장의 표현을 다듬는 것만으로는 결과의 품질이 정해지지 않고, 요청에 목적, 입력, 출력 형식, 완료 기준이 담겼는지에 따라 결과가 달라집니다. (Q-123 권장안으로 반영된 문안. 그대로)
- 이 장을 읽고 할 수 있게 되는 것(세 가지):
  1. 하나의 요청에 목적, 입력, 출력 형식, 완료 기준이 모두 있는지 점검하고 누락된 요소를 채울 수 있다.
  2. 여섯 방법(구체적 지시, 이유 제공, 예시 제공, 구획 구분, 할 일로 지시, 행동 동사)으로 요청 문장을 명확하게 고칠 수 있다.
  3. 받은 결과를 완료 기준과 대조하고, 요청을 다듬어도 남는 문제(자료의 양과 선별, 반복 작업의 일관성, 결과 검증)를 컨텍스트 설계와 하네스의 설정으로 넘길 수 있다.
