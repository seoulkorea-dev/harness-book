# 그림 2-1 명세

- 목적(결론 한 문장): 다섯 구성 요소를 모두 정해야 에이전트의 결과를 받아들일 근거가 생깁니다.
- 그림이 들어갈 절: 다섯 구성 요소(id="components"), 대표 그림
- 형태 후보 두 가지(시안 두 개로 그림):
  1. **묶음 나무와 카드(지금 형태를 다듬은 안).** 왼쪽에 "하네스의 다섯 구성 요소"가 지시, 실행 수단, 강제의 세 묶음으로 갈라지고, 오른쪽에 구성 요소 카드 다섯 장이 세로로 놓입니다. 카드는 "정할 것 → CR에서 채움 → 이유"의 세 칸입니다. 카드 머리에 작동하는 루프 단계를 표시합니다. 폭은 960입니다(가장 작은 글자 20px).
  2. **루프 단계 띠와 행렬.** 맨 위에 가로 띠로 루프 단계(그림 1-2의 다섯 단계)를 왼쪽에서 오른쪽으로 둡니다. 그 아래 행렬은 행이 다섯 구성 요소, 열이 정할 것, CR에서 채움, 이유입니다. 각 행에서 위쪽 띠의 작동 단계로 직각 지시선을 긋습니다. 행 왼쪽에 묶음 이름표(지시, 실행 수단, 강제)를 붙입니다. 폭은 960입니다(가장 작은 글자 20px).

## 반드시 보여 줄 것
| 구성 요소(본문 용어 그대로) | 한 줄 역할 |
|---|---|
| 역할 | 에이전트와 사람의 작업 경계 |
| 도구 | 작업에 쓸 기능과 노출 범위 |
| 권한 | 허용, 확인, 금지할 동작 |
| 기록 | 세션 뒤에 남길 결정과 진행 |
| 검증 | 완료 조건과 확인 방법 |
| 묶음: 지시(역할, 기록), 실행 수단(도구), 강제(권한, 검증) | 본문 첫 절에서 먼저 밝히는 분류(지금 본문 8행) |
| CR에서 채움(카드 중심, 파랑 막대와 굵은 글자) | 역할: CLAUDE.md 작업 순서, 승인 작업 / 도구: 내장 도구, 웹 접근 금지, 검토 에이전트는 읽기 도구만 / 권한: 허용, 확인, 금지 규칙 / 기록: 결정 기록, tasks.json 통과 값, 인계 메모, 커밋 / 검증: 편집 뒤 훅, check.py, 검토 에이전트 |

## 반드시 보여 줄 관계
| 시작 | 끝 | 화살표 이름(동사나 데이터) | 순서(먼저 일어나는 것부터 번호) |
|---|---|---|---|
| 하네스의 다섯 구성 요소 | 세 묶음 | 하는 일로 묶음 | 1 |
| 루프 단계 "컨텍스트 구성" | 역할 | 규칙 문서 읽음 | 2 |

- **작가 확인:** 작동 단계 표시가 지금 그림 2-1과 표 1-6(그림 1-2의 단계별 구성 요소)에서 다릅니다.
  - 표 1-6: 컨텍스트 구성 역할, 권한 확인 권한, 도구 실행 도구, 최종 응답 기록, 최종 응답 전 검증
  - 지금 그림 2-1: 역할과 기록 1단계, 도구 2단계, 권한 3단계, 검증 4단계 뒤
  - 이 명세는 표 1-6에 맞추되 두 가지만 남기는 안입니다. 도구는 "판단과 응답"(모델이 노출된 도구에서 고름), 검증은 "도구 실행 뒤"(편집 뒤 훅)입니다.
  - 어느 쪽에 맞출지, 표 1-6도 함께 고칠지 정해 주십시오.

- 본문에 없는 분류, 제품명과 회사명(Claude Code, .claude 등. "설정 폴더", "규칙 문서"로 씀), 영어 병기(allow, deny는 "허용", "금지")
- 상자로 감싼 요약이나 "그래서 할 일" 띠(맨 아래 "*" 한 줄로 바꿈), 경고 색(이 그림에는 멈추는 곳이 없음)
- "비어 있으면" 같은 가정으로 시작하는 카드 문구
