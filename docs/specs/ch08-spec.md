## 절 첫 문단(왜 → 무엇 → 어떻게 → 근거)
- 장 첫 문단: 작동(새 세션은 새 컨텍스트에서 시작) → 한계(대화에서만 합의한 내용은 세션이 끝나거나 압축되면 사라짐) → 결과(같은 논의와 실수 반복) → 행동(저장소 문서로 기록) → 범위(기록의 종류, 결정 기록의 형식, 인계 메모, 실행 로그를 다루고 CR에 적용). 주장 줄 되풀이 문장 삭제. 세션의 뜻 한 구절(에이전트와 한 번 대화를 시작해 끝낼 때까지)과 일상 장면 한 줄(어제 대화를 새 창에서 이어 가려는 상황)
- session: 왜(세션 사이에 작업 상태가 이어지지 않음, Young 2025) → 무엇(이 책은 저장소의 문서와 커밋을 이어 가는 기준으로 삼음. 대화 기록과 자동 메모리도 로컬에 남지만 보관 기간이 있고 팀이 함께 검토할 수 없음, S-C8-1~3) → 근거(Claude Code 문서: 세션은 독립, CLAUDE.md와 자동 메모리가 전달, Codex 인용: 접근할 수 없는 지식은 없는 것과 같음) → 반론과 답(대화 이력에 모두 남아 있다: 같은 세션을 --resume으로 이어 갈 수는 있지만 다른 에이전트나 새 세션은 읽지 못하고, 이어 간 세션도 압축되면 이른 지시를 잃음, 5장 링크) → 다음 절 연결
- kinds: 왜(질문이 셋: 왜 그렇게 정했나, 어디까지 했나, 늘 무엇을 지키나. 갱신 시점이 달라 한 문서에 섞으면 새 세션이 무엇을 믿을지 모름) → 무엇(이 책의 정리: 세 종류, 인계 메모는 셋을 묶어 넘기는 문서, 2장 기록 구성 요소와의 관계 한 줄) → 어떻게(표 8-1. 규칙 문서 작성과 갱신은 5장 링크로 상기) → 근거(진행 기록의 효과는 Young 2025, 진행 기록 설명 뒤)
- decisions: 왜(변경 이유가 없으면 폐기된 결정으로 돌아감) → 무엇(이 책이 정리한 형식: 번호, 날짜, 결정, 대체, 이유) → 어떻게(삭제하지 않고 대체로, 일반 형식 예. CR 예시는 example 절) → 근거(이 책의 저장소도 같은 형식으로 작업 전에 읽게 함, 한 문장)
- handover: 왜(규칙 문서는 모든 세션에 같고 현재 상태는 세션마다 다름) → 무엇(이 책의 정리: 다섯 항목) → 어떻게(항목 목록) → 근거(Young 2025의 진행 파일과 git 로그가 가장 가까운 근거, 다섯 항목은 이 책의 설계임을 밝힘). 책 제작 채팅 문단과 "기록과 인계는 …" 원칙 비슷한 문장 삭제
- logs: 왜(완료 보고를 확인하려면 실제로 한 일의 기록이 필요, 7장 report 링크) → 무엇(이 책은 하네스가 자동으로 남기는 기록을 실행 로그라고 부름, 네 가지: 세션 기록, 실행 결과, 훅 기록, 조직 지표) → 어떻게(정할 것 세 가지: 보관 기간, 추적 지점, 확인 방법) → 근거(S-C8-1, 2, 4, 5, 6). 용어는 한 줄씩 풀이(JSONL은 한 줄에 한 항목씩 적는 텍스트 파일, OpenTelemetry는 지표를 조직의 관측 시스템으로 보내는 표준 방식이며 켜야 동작, 훅은 2장 링크로 상기). 개인 사용자는 세션 기록과 실행 결과, 조직 관리자는 조직 지표라는 구분 한 줄
- example: 왜(CR을 두 세션에 나눌 때 기록이 하는 일을 한 사례로) → 무엇(작업 번호는 6장 표 6-4의 작업 1~5, 세션 1이 작업 2, 3을 마치고 세션 2가 작업 4부터 시작하는 상황, 실습 5, 6과 같음) → 어떻게(표 8-x: 세션 1이 남긴 결정 기록, 진행 기록, 인계 메모와 갱신 주체(결정 기록은 사람, 진행 기록의 통과 값과 HANDOFF.md는 에이전트, 예제 CLAUDE.example.md의 수정 범위), 세션 2가 읽는 순서는 예제 규칙 문서의 순서(CR.md, DECISIONS.md, tasks.json, HANDOFF.md)) → D-012, D-015 결정 기록 예시(실습 폴더에는 D-012만, D-015는 이 장의 예시, 읽는 법 한 줄) → CR 인계 메모 예(다섯 항목 값) → 대화 이어 가기(--resume)와 인계 메모의 차이 한 줄 → 실습 6 링크
