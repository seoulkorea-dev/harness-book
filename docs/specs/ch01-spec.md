# Chapter 1 명세

- 장 제목: 하네스란 무엇인가
- 주장 한 줄: 에이전트는 모델과 하네스로 이루어집니다. (지금 주장 줄 유지, 관계를 서술하는 문장이라 플레이북 3.2에 맞음)
- 이 장을 읽고 할 수 있게 되는 것(세 가지):
  1. 에이전트에 맡긴 요청 하나를 놓고, 모델이 하는 일(판단, 응답, 도구 호출 요청)과 하네스가 하는 일(도구 실행, 컨텍스트 관리, 루프 실행, 권한 확인, 검증)을 나눠 말할 수 있다.
  2. 쓰고 있는 에이전트 제품에서 제품이 제공하는 실행 장치와 사용자와 팀이 정하는 설정을 구분하고, 설정을 다섯 구성 요소(역할, 도구, 권한, 기록, 검증)로 나눠 볼 수 있다.
  3. 결과가 기대와 다를 때 증상에서 먼저 의심할 곳(프롬프트, 컨텍스트, 하네스의 설정)을 정하고, 컨텍스트, 권한, 종료 사유, 사용량을 명령과 화면으로 확인할 수 있다.

## 용어
| 용어 | 이 장에서의 뜻 | 처음 정의한 곳 |
|---|---|---|
| 에이전트 | 인공지능 모델이 루프 안에서 도구를 사용해 다음 행동을 스스로 정하고, 결과를 확인하며, 목표를 이룰 때까지 반복하는 시스템. 모델과 하네스로 이루어짐 | 도입부 둘째 문단(루프를 뺀 같은 문장), agent-harness에서 루프를 넣은 작가 문안 |
| 하네스 | 모델이 에이전트로 일할 수 있게 하는 모델 바깥의 실행 체계 전체 | 도입부 둘째 문단 |
| 실행 장치, 설정 | 하네스 가운데 제품이 제공하는 층, 사용자와 팀이 정하는 층 | 도입부 둘째 문단(한 줄), agent-harness(목록) |
| 다섯 구성 요소 | 설정에서 정하는 역할, 도구, 권한, 기록, 검증 | 도입부 둘째 문단에서 "다섯 가지 구성 요소", agent-harness에서 하나씩 |
| 토큰, 대규모 언어 모델, 컨텍스트, 컨텍스트 윈도 | BOOK_SPEC 5절 용어표 | background(두 문단으로 나눠 정의) |
| 도구, 도구 호출 | 모델 바깥에서 실행되는 기능, 그 실행을 모델이 요청하는 것 | background |
| 권한 규칙, 격리 환경 | 도구 호출을 허용, 확인 요청, 금지로 나눠 정한 규칙, 팀이 정한 폴더 밖의 파일이나 네트워크에 닿지 못하게 막은 실행 공간 | background 둘째 목록(실행 범위) |
| 시스템 프롬프트, 규칙 문서, 도구 정의 | 제품이 미리 포함하는 지시, 작업 규칙을 적어 프로젝트에 두는 파일, 도구의 이름과 설명과 입력 형식 | request |
| 완료 기준 | 작업이 끝났다고 판정하는 조건 | request |
| 세션, 세션 기록 | 에이전트와 한 번 대화를 시작해 끝낼 때까지, 그 대화를 저장해 이어 가게 하는 기능 | agent-harness |
| 외부 실행 환경, MCP | 도구가 읽거나 변경하는 대상 전체, 외부 도구를 연결하는 표준 방식 | agent-harness |
| 에이전트 루프, 턴 | 컨텍스트 구성, 판단과 응답, 권한 확인, 도구 실행, 최종 응답의 다섯 단계, 문서마다 범위가 다른 단위(어느 문서 기준인지 밝힘) | loop |
