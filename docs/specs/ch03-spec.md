# Chapter 3 명세

- 장 제목(목차 그대로): 하네스로 에이전트 설계하기
- 주장 한 줄(장 제목 아래에 둘 문장): 에이전트의 동작을 정하는 것은 요청 문장이 아니라, 목적부터 승인 지점까지 하네스에 정해 둔 항목입니다. (지금 주장 줄 유지, src/site.json ch03)
- 독자가 이 장을 읽고 할 수 있게 되는 것(세 가지):
  1. 맡길 업무 한 건에 대해 명세서의 아홉 항목(목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점)에 값을 채울 수 있다.
  2. 에이전트가 수정할 수 있는 파일과 수정할 수 없는 파일을 나누고, 검증 기준(수용 시험, 검사 스크립트)을 수정 금지로 두는 이유를 말할 수 있다.
  3. 명세서 항목을 규칙 문서, 권한 설정, 훅, 하위 에이전트 정의 파일로 옮기고, 적용되었는지 화면과 검사 출력으로 확인할 수 있다.

## 범위와 개정 방향
- 지금 원고를 바탕으로 장 틀을 보강하고 그림 규칙(FIGURE_STYLE.md, D-109의 경고 색 삭제, 맨 아래 "*" 한 줄)을 적용한다. 절 구성은 유지한다.
- 절과 앵커: 에이전트 명세서(spec), 기능 추가 에이전트: CR 구현(example), 제품 파일로 옮기기(files), 실패와 막는 장치(fail), 확인 방법(check), 원칙과 점검 질문(principle), 참고 자료(refs).
- 다른 장이 링크하는 앵커(example 9곳, files 1곳, principle 1곳)는 이름을 바꾸지 않는다.
- 장 틀의 "CR 적용"은 example 절(표 3-2, 그림 3-1)과 files 절(표 3-4, 설정 코드)이 맡는다.
- 2장과 용어를 맞춘다: "코드 원본" → "원본 자료(data/projects.csv)", 사람의 승인 범위(수용 기준 확정, 작업 5 승인, commit 확인, push). 표 3-2, 표 3-3, 그림 3-1, aria-label, 본문 문장을 한꺼번에 맞춘다. "설정"은 "설정 폴더"로 통일
