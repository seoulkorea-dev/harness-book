# 그림 9-1, 9-2 명세(9장 개정)

## 그림 9-1
- 예제 사실 없음, 제품 설정 이름(allow, ask, deny)을 단독 영문으로 쓰지 않고 한국어 이름(허용, 확인 요청, 금지)으로, 명령 예 없음, 앰버 없음(D-116, D-095)
- 목적(결론 한 문장): 동작의 위험에 따라 허용, 확인 요청, 금지를 나누고, 접근 범위는 격리로 보완합니다
- 그림이 들어갈 절: permissions
- 형태 후보 두 가지: 1. 흐름형(그림 1-2, 2-2 기준): 도구 호출 요청 → 1 금지 규칙 → 2 확인 요청 규칙 → 3 허용 규칙 → 어디에도 없으면 권한 모드. 바깥을 격리 영역이 감쌈. 2. 구성형: 왼쪽 영역 "동작의 위험에 따른 규칙"(세 카드: 되돌릴 수 있음 → 허용, 사람이 보고 진행 → 확인 요청, 사람이 직접 → 금지), 오른쪽 영역 "평가 순서", 아래 띠 "격리: 운영 체제 수준 접근 제한"

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 도구 호출 요청 | 모델이 요청한 도구 실행 |
| 금지 규칙 | 일치하면 실행하지 않음, 사람이 직접 할 동작 |
| 확인 요청 규칙 | 일치하면 사람이 승인하거나 거절, 사람이 보고 진행을 정할 동작 |
| 허용 규칙 | 일치하면 확인 없이 실행, 되돌릴 수 있는 동작 |
| 권한 모드 | 어느 규칙에도 없을 때의 처리 |
| 격리 | 셸 명령과 하위 프로세스의 파일, 네트워크 접근을 운영 체제 수준에서 제한, 규칙과 별도 |

### 반드시 보여 줄 관계
| 시작 | 끝 | 화살표 이름 | 순서 |
|---|---|---|---|
| 도구 호출 요청 | 금지 규칙 | 먼저 대조 | 1 |
| 금지 → 확인 요청 → 허용 | 다음 규칙 | 일치하지 않으면 | 2 |
| 허용 규칙 | 권한 모드 | 어디에도 없으면 | 3 |
| 격리 | 실행되는 명령 | 문자열과 관계없이 제한(회갈) | - |

### 맨 아래 "*" 한 줄
- * 규칙은 명령 문자열만 대조하므로, 문자열과 관계없이 막을 접근은 격리로 제한

## 그림 9-2
- 예제 사실, 제품 명령(/usage, /status), 항목 이름(Session) 없음
- 목적: 비용 기준은 작업을 시작하기 전에 정하고, 한도에 이르면 사람이 계속 여부를 정합니다
- 그림이 들어갈 절: cost
- 형태 후보 두 가지: 1. 흐름형 세로(번호 단계: 시작 전에 정함(세 기준) → 실행 중 확인(사용량 화면, 추정치) → 한도 도달 시 사람이 결정). 2. 구성형: 위 영역 "시작 전에 정함" 세 카드, 아래 두 상자(실행 중 확인, 한도 도달) 가로 흐름

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 작업 단위의 크기 | 한 세션에 끝나는 크기로 나누면 다시 실행하는 비용이 줄어듦 |
| 읽힐 자료의 범위 | 세션마다 읽히는 상시 규칙 문서를 짧게 |
| 지출 한도 | 팀이나 사용자별 한도 |
| 실행 중 확인 | 제품의 사용량 화면, 금액은 추정치 |
| 한도 도달 | 사람(승인자)이 계속 여부를 결정 |

### 반드시 보여 줄 관계
