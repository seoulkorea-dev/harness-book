## 1. 기준(결정 D-115)
- 그림 종류는 두 가지입니다.
  - 원리 그림: 장의 원리를 보여 주는 그림. 일반 내용으로 그리고 예제(CR) 사실을 넣지 않습니다. 예제에서 어떻게 채웠는지는 표와 본문(장 틀의 CR 적용)이 맡습니다.
  - 예제 그림: 장의 주제 자체가 예제 설계인 그림(예: 그림 3-1). 캡션에 예제임을 밝히고, 그림 안 예제 사실은 D-114대로 "예제"로 표기합니다.
- 그림 명세 틀에 "그림 종류: 원리 / 예제" 칸을 둡니다.
- D-111의 1장 기준 일관성에 "담는 내용의 종류(원리, 예제)도 1장과 같게"를 더합니다(그림 1-1, 1-2는 원리 그림이며 예제가 없음).

- editor 점검 5번과 figure-checker 점검에 "원리 그림에 예제 사실이 섞였는가"를 필수 항목으로 넣습니다.

## 2. 그림 2-1 명세
- 그림 종류: 원리
- 목적(결론 제목, 그대로): 다섯 구성 요소를 모두 정해야 결과를 받아들일 근거가 생깁니다
- 부제: 구성 요소마다 정할 것, 이유, 주로 작동하는 루프 단계
- 형태 후보(시안 두 개): 1. 세 묶음을 위에서 아래로 놓고 구성 요소를 행으로(정할 것, 이유 두 칸) 2. 세 묶음을 세 열로 나란히 놓고 구성 요소를 열 안의 카드로

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 묶음 지시(역할, 기록) | 규칙 문서와 기록 파일로 판단 안내 |
| 묶음 실행 수단(도구) | 노출된 도구로 작업 수행 |
| 묶음 강제(권한, 검증) | 권한 규칙과 훅, 검사로 통제 |
| 구성 요소 다섯 | 정할 것과 이유(지금 그림의 문구 그대로), 주로 작동하는 단계(그림 1-2 번호, 검증은 번호 없는 완료 기준 확인) |

### 쓰지 않을 것
- "CR에서 이렇게 채움" 칸과 그 내용(규칙 문서의 작업 순서, 작업 5, 결정 기록, 웹 접근 금지 등 모두 표 2-1에 있음)
- 캡션과 접근성 설명의 "예제 CR"

### 맨 아래 "*" 한 줄(그대로)
- 반드시 지킬 규칙은 권한 규칙과 훅으로 강제, 나머지는 규칙 문서로 안내

### 캡션과 본문
- 캡션: "그림 2-1. 하네스의 다섯 구성 요소 (이 책의 정리)", 설명: "세 묶음, 구성 요소별로 정할 것과 이유, 주로 작동하는 단계"
- 본문: "그림 2-1과 표 2-1의 예는 … CR입니다" → "표 2-1의 예는 … CR입니다". 그림 소개 문장에서 "CR에서 채운 방법"을 빼고, CR에서 채운 방법은 표 2-1이 보여 준다고 적음
- 해설표: 그림 2-1은 표 2-1이 구성 요소별 설명을 맡음(지금과 같음)

## 4. 그림 4-1 명세
- 그림 종류: 원리
- 목적(결론 제목, 그대로): 목적과 완료 기준은 요청하는 사람만 줄 수 있습니다
- 부제: 네 요소로 구성한 요청이 모델의 결과와 결과 확인으로 이어지는 구조("(예제: 변경 요청의 영향 검토)" 삭제)
- 형태 후보(시안 두 개): 1. 요청 영역을 왼쪽에 세로로(네 요소 카드), 오른쪽에 모델의 결과 → 결과 확인을 세로로 2. 요청 영역을 위에 가로로(네 요소 카드 한 줄), 아래에 모델의 결과 → 결과 확인을 가로로

### 반드시 보여 줄 것
| 구성 요소(본문 용어) | 한 줄 역할 |
|---|---|
| 요청(영역) | 네 요소로 구성한 요청 한 건 |
| 목적 | 결과를 누가 어디에 사용하는지(요청하는 사람만 아는 정보, 연한 파랑) |
| 입력 | 판단에 필요한 자료와 범위 |
| 출력 형식 | 항목, 표 구성, 분량 |
| 완료 기준 | 결과를 받아들일 조건(요청하는 사람만 아는 정보, 연한 파랑) |
| 모델의 결과 | 누락된 요소를 추측으로 채움 |
| 결과 확인(번호 없는 확인 상자) | 요청하는 사람이 완료 기준으로 판정 |

### 반드시 보여 줄 관계
| 시작 | 끝 | 화살표 이름 | 순서 |
|---|---|---|---|
| 요청 | 모델의 결과 | 요청 전달 | 1 |
| 모델의 결과 | 결과 확인 | 결과 대조 | 2 |
| 완료 기준 | 결과 확인 | 확인에 다시 사용(회갈 점선) | 3 |

### 쓰지 않을 것
- 예제 요청 문장(운영 위원회, 변경 요청, 다섯 항목, 세 선택지 등). 예제 요청은 본문 "네 요소를 갖춘 요청" 절과 표가 맡음
- "예제 요청문" 영역 이름

### 맨 아래 "*" 한 줄(그대로)
- 요청을 보내기 전에 네 요소가 모두 있는지 점검

### 캡션, 해설표
- 캡션: "그림 4-1. 요청의 네 요소와 결과 (프롬프트 작성 문서를 바탕으로 이 책이 정리)", 설명 "네 요소가 결과와 결과 확인에 이어지는 구조"
- 표 4-2: "예제 요청문" 행 → "요청" 행(네 요소로 구성한 요청 한 건. 예제 요청은 "네 요소를 갖춘 요청" 절)
