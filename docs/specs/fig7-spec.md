# 그림 7-1, 7-2 명세(7장 개정)

## 그림 7-1
- 예제 사실 없음: 그림, 접근성 설명, 캡션에 CR 사실과 예제 파일 이름을 넣지 않음(D-116)
- 목적(결론 한 문장): 완료는 보고가 아니라, 기준 항목마다 고른 검증 방법의 결과로 판정합니다
- 그림이 들어갈 절: methods(검증 방법의 선택)
- 형태 후보 두 가지: 1. 흐름형(그림 1-2 기준): 위에서 아래로 산출물 → 기준 항목마다 방법 선택(세 방법이 나란한 상자) → 판정 → 통과/미통과. 2. 구성형(그림 1-1 기준): 왼쪽 영역 "증거"(세 방법 카드), 오른쪽 영역 "판정"(통과, 다시 작업), 완료 보고는 바깥 회갈 영역

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 산출물 | 에이전트가 만든 코드, 문서, 화면 |
| 완료 보고 | 만든 쪽의 판단, 판정 근거가 아님(회갈, 점선 연결 없음) |
| 기준 항목 | 변환한 완료 기준 하나 |
| 자동 검사 | 스크립트와 테스트가 판정 |
| 출력 확인 | 사용자가 출력과 산출물을 직접 확인 |
| 독립 검수 | 결과를 만들지 않은 에이전트나 사람이 검토 |
| 판정 | 통과 또는 미통과 |
| 다시 작업 | 미통과면 오류 출력을 돌려 같은 단위를 다시 |
| 다음 작업 단위 | 통과면 다음으로 |

| 완료 보고 | (연결 없음) | 판정 근거 아님 | - |

## 그림 7-2
- 예제 사실 없음(D-116)
- 목적: 판단이 필요한 기준은 기준표와 예시 답안으로 만든 쪽이 아닌 채점자가 판정하고, 판정값을 통과 조건과 비교합니다
- 그림이 들어갈 절: rubric
- 형태 후보 두 가지: 1. 흐름형 가로(입력 묶음 → 채점 → 판정값 → 통과 조건 비교, 미통과 되돌림). 2. 흐름형 세로(그림 1-2처럼 번호 단계)
- 기존 그림 7-2(세 채점 방법의 비교, 표 모양)는 표 7-4로 옮김

### 반드시 보여 줄 것
| 구성 요소 | 한 줄 역할 |
|---|---|
| 결과 | 채점할 산출물 |
| 기준표 | 통과 조건을 항목별로 적은 표 |
| 예시 답안 | 기준이 되는 정답 |
| 채점 | LLM(결과를 만든 모델과 다른 모델) 또는 사람 |
| 판정값 | 정답/오답, 1~5점처럼 구체적인 값 |
| 통과 조건 | 판정값의 통과 기준(예: 4점 이상) |
| 다시 작업 | 미달이면 판정 근거를 돌려 다시 |

### 반드시 보여 줄 관계
| 시작 | 끝 | 화살표 이름 | 순서 |
|---|---|---|---|
| 결과, 기준표, 예시 답안 | 채점 | 함께 입력 | 1 |
| 채점 | 판정값 | 판정 | 2 |
| 판정값 | 통과 조건 | 비교 | 3 |
| 통과 조건 | 다시 작업 | 미달: 판정 근거 전달(회갈 점선) | 4 |

### 맨 아래 "*" 한 줄
