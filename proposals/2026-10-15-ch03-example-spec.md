## 1. 이 예제가 3장에서 하는 일

- 3장의 에이전트 명세서 아홉 항목(목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점)이 모두 필요해지는 업무에 명세서를 적용합니다.
- 주간 보고서 예제로는 보여 주기 어려웠던 다섯 가지를 보여 줍니다.
  - 여러 작업 단위와 단위별 종료 조건
  - 편집 도구와 실행 도구가 함께 있는 권한 설계
  - 에이전트가 고칠 수 있는 테스트와 고칠 수 없는 수용 시험의 구분(검증 기준 보호)
  - 두 세션에 걸친 작업과 인계 메모
  - 사람의 승인 지점(commit 확인, 통합 시나리오 승인, push는 사람만)
- 독자는 코드를 작성하지 않습니다. 에이전트가 작성한 코드는 읽기용이고, 독자가 실행하는 것은 앱 실행, 테스트, Claude Code입니다.

## 3. 구현 전 앱 상태와 CR-07 수용 기준

### 3-1. 구현 전 앱(기준 상태)

- 정산 요청 목록 화면, 등록 화면, 등록 처리(필수 항목 검사 포함)
- 정산 요청 항목: 요청 번호, 요청자, 날짜, 금액, 사용처, 상태
- `data/expenses.json`에 기존 요청 몇 건(프로젝트 코드 없음)
- 단위 테스트는 모두 통과하는 상태로 시작

### 3-2. CR-07 수용 기준 (`docs/CR-07.md`, `acceptance/`에 시험으로 구현)

1. 등록 화면에서 `data/projects.csv`의 프로젝트 코드를 선택할 수 있다.
2. 목록에 없는 프로젝트 코드로 등록하면 거부하고 사유를 표시한다.
3. 프로젝트 코드는 등록 시 필수다(D-012 조건부 수용 조건은 작성 쪽이 원고와 맞춰 확정).
4. 목록 화면에 프로젝트 코드를 표시한다.
5. 프로젝트 코드가 없는 기존 요청도 목록에 그대로 표시된다(6장 CR-07-2 완료 기준 "기존 데이터 유지").
6. `data/projects.csv`는 변경되지 않는다.

## 5. 제품 파일 설계

### 5-1. CLAUDE.md에 담을 항목

- 이 저장소의 목적과 CR-07 한 줄 요약, 읽는 순서(입력 항목 순서)
- 작업 순서: tasks.json에서 "통과": false인 첫 작업 단위만 수행
- 완료 기준: `python check.py` 통과 전에는 완료로 보고하지 않음, 보고에 check.py 출력 원문 포함
- 수정 범위: acceptance/, data/, check.py는 수정하지 않으며, 수용 시험이 실패하면 시험이 아니라 구현을 고침
- 중단 규칙: 같은 시험 세 번 연속 실패 시 중단하고 HANDOFF.md 작성
- 세션 종료 시 HANDOFF.md 항목: 8장 인계 메모 항목(현재 상태, 읽을 문서, 미결정, 다음 작업, 확인 명령)
- Windows와 다른 환경의 명령 차이(`python`, `python3`)는 README와 settings.json 양쪽에서 처리

### 5-2. `.claude/settings.json` 설계

- allow: `Bash(python -m unittest*)`, `Bash(python check.py)`, `Bash(python3 -m unittest*)`, `Bash(python3 check.py)`, `Bash(git status)`, `Bash(git diff*)`, 허용 경로의 Read, Edit
- ask: `Bash(git commit *)`
- deny: `Edit(./data/**)`, `Edit(./acceptance/**)`, `Edit(./check.py)`, `Edit(./CLAUDE.md)`, `Edit(./DECISIONS.md)`, `Edit(./.claude/**)`, `Bash(git push *)`, `WebFetch`, `WebSearch`
- hooks: 파일 편집 도구 실행 뒤(PostToolUse, 편집 계열 도구 matcher) 단위 테스트 실행
- 규칙 문자열, 훅 이벤트 이름과 형식은 작성 시점의 Claude Code 공식 문서(Configure permissions, Hooks)로 확인하고 research 기록에 남깁니다. 이 설계서의 표기는 개념 수준입니다.

### 5-3. 검토 하위 에이전트 (`.claude/agents/reviewer.md`)

- 역할: git diff와 docs/CR-07.md를 읽고 수용 기준 1~6별로 충족, 미충족, 확인 불가를 보고
- 도구: 읽기 도구만(편집, 실행 도구 없음)
- 출력: 수용 기준별 표와 근거 위치(파일, 줄)

### 5-4. tasks.json

- 6장의 JSON 형식("id", "작업", "완료 기준", "확인 방법", "통과")을 그대로 사용, CR-07-2~5 네 항목
- CR-07-5의 "통과"는 PM 승인 뒤 사람이 변경
