Chapter 4 하네스의 구성 요소

에이전트(Agent)는 주어진 역할 안에서, 연결된 도구를 사용해, 허용된 권한 범위의 작업을 수행합니다. 하네스(Harness)의 품질을 정하는 것은 연결한 도구의 수가 아니라, 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소를 모두 정했는지입니다. 그래서 도구만 연결하고 권한, 기록, 검증을 정하지 않으면, 결과를 받아들일 근거가 없습니다. 따라서 관리자는 구성 요소마다 무엇을 결정해야 하는지 알고 있어야 합니다. 이 장에서는 하네스의 다섯 구성 요소와 구성 요소별 결정 항목을 살펴봅니다.

  • 하네스는 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소로 설계합니다.
  • 규칙 문서는 지시이고, 권한 규칙과 훅은 강제입니다.
  • 반드시 지켜야 하는 규칙은 강제 수단으로 처리합니다.

다섯 구성 요소

Chapter 1의 주간 보고서 예제는 다섯 구성 요소로 하네스를 설정했습니다. 역할은 에이전트가 맡는 작업의 범위입니다. 도구는 에이전트가 사용할 수 있는 기능입니다. 권한은 도구로 할 수 있는 동작의 범위입니다. 기록은 다음 작업에 넘길 정보입니다. 검증은 결과를 받아들이기 전에 확인하는 절차입니다.

그림 4-1은 다섯 구성 요소를, 표 4-1은 구성 요소별로 관리자가 정할 결정과 Claude Code의 구현 방법을 보여 줍니다.

Claude Code의 구현 열은 2026년 10월에 확인한 공식 문서 기준입니다. Codex의 구현 방법은 Chapter 9의 제품 단위 비교에서 다룹니다.

표 4-1의 하위 에이전트(Subagent)는 특정 작업을 맡도록 별도로 정의한 에이전트입니다. MCP(Model Context Protocol)는 외부 시스템의 기능을 에이전트의 도구로 연결하는 규약이며, 이를 구현한 서버를 MCP 서버라고 합니다. 자동 메모리는 Claude Code가 작업 중의 수정 요청과 선호를 스스로 기록하고 다음 세션에 읽는 기능입니다.

에이전트 루프와 종료 조건

다섯 구성 요소는 에이전트가 일하는 순서 안에서 서로 다른 시점에 작동합니다. Anthropic의 Agent SDK 문서는 Claude Code의 실행 루프를 다섯 단계로 설명합니다(Anthropic, 2026b).

  • 요청 수신: 모델이 요청과 함께 시스템 프롬프트, 도구 정의, 대화 이력을 받습니다.
  • 판단과 응답: 모델이 현재 상태를 판단해 텍스트로 답하거나 도구 호출을 요청합니다.
  • 도구 실행: 하네스가 요청된 도구를 실행하고 결과를 모델에 돌려줍니다.
  • 반복: 판단과 도구 실행을 반복합니다. 이 왕복 한 번을 턴이라고 부릅니다.
  • 결과 반환: 모델이 도구 호출 없이 응답하면 루프가 끝나고, 최종 응답과 토큰(Token) 사용량, 비용, 세션 ID가 반환됩니다.

그림 4-2는 이 루프와 종료 조건을, 표 4-2는 루프의 단계별로 작동하는 구성 요소를 보여 줍니다.

도구 실행 앞에서는 권한이 작동합니다. 문서에 따르면 거부된 도구 호출은 실행되지 않고, 모델은 거부 메시지를 결과로 받습니다. 모델은 다른 방법을 찾거나, 진행할 수 없다고 보고합니다.

루프는 기본적으로 모델이 스스로 끝낼 때까지 계속됩니다. 문서는 범위가 분명한 작업에서는 문제가 없지만, 열린 요청에서는 루프가 오래 실행될 수 있다고 설명합니다. 그래서 하네스는 두 가지 상한을 둡니다. 턴 상한은 도구를 사용한 턴의 수를, 비용 상한은 지출 금액을 제한합니다. 문서는 운영 환경의 에이전트에 비용 상한을 기본으로 두라고 권합니다(Anthropic, 2026b).

상한에 도달하면 루프는 작업을 마치지 못한 채 끝나고, 결과에 종료 사유가 남습니다. 종료 사유는 정상 완료, 턴 상한 도달, 비용 상한 도달, 실행 중 오류 등으로 구분됩니다. 상한에 도달한 결과는 완료로 판정하지 않습니다(Chapter 6의 완료 보고). 관리자는 두 상한의 값과, 상한에 도달했을 때 세션을 재개할지 중단할지를 미리 정합니다. 비용 상한의 기준은 Chapter 8의 비용 관리와 연결됩니다.

Codex도 같은 구조의 루프를 사용합니다. OpenAI는 Codex의 하네스가 모든 Codex 제품에 공통인 에이전트 루프를 제공한다고 설명합니다. 턴이라는 말의 범위는 두 제품이 다릅니다. Agent SDK 문서의 턴은 도구 호출 왕복 한 번이고, OpenAI 글의 턴은 사용자 메시지 하나에 대한 처리 전체입니다. 한 턴 안에서 모델 추론과 도구 호출이 여러 번 반복됩니다. OpenAI는 에이전트가 한 턴에서 수백 번의 도구 호출을 할 수 있다고 설명합니다. 그러면 컨텍스트 윈도(Context Window)를 모두 소진할 수 있습니다(OpenAI, 2026). 두 제품을 함께 운영한다면 턴 상한을 정하기 전에 제품마다 턴이 무엇을 세는지 확인해야 합니다.

도구 노출 범위

도구를 많이 연결할수록 에이전트가 할 수 있는 일은 늘어나지만, 비용도 함께 늘어납니다. Agent SDK 문서에 따르면 내장 도구의 정의는 요청마다 컨텍스트(Context)에 들어가고, 도구 정의 하나하나가 컨텍스트 공간을 차지합니다. 문서는 도구를 선별해서 연결하고, 하위 에이전트에는 필요한 최소한의 도구만 지정하라고 안내합니다(Anthropic, 2026b).

Claude Code는 도구 노출을 줄이는 장치를 둡니다. MCP 서버의 도구 정의는 기본적으로 바로 불러오지 않고, 도구 이름과 서버 안내만 컨텍스트에 둔 뒤 필요할 때 불러옵니다. 비용 문서는 gh, aws 같은 명령줄 도구가 도구 목록을 추가하지 않아 MCP 서버보다 컨텍스트를 적게 차지한다고 설명합니다. 사용하지 않는 서버는 끄라고 안내합니다(Anthropic, 2026b).

노출 범위는 권한과 함께 정합니다. 연결된 도구라도 허용 목록에 없는 도구는 실행 전에 확인을 거치고, 금지 목록의 도구는 실행되지 않습니다. 문서에 따르면 읽기 전용 도구는 동시에 실행될 수 있고, 상태를 변경하는 도구는 충돌을 막기 위해 차례로 실행됩니다. 그림 4-3은 도구 노출 범위를 정하는 네 가지 장치입니다.

관리자가 정할 것은 세 가지입니다.

  • 작업에 연결할 도구: 작업 단위마다 필요한 도구만 연결합니다.
  • 읽기와 수정의 구분: 조회만 필요한 작업에는 읽기 도구만 허용합니다.
  • 하위 에이전트의 도구: 하위 에이전트에는 맡긴 작업에 필요한 최소한의 도구만 지정합니다.

지시와 강제

구성 요소를 구현하는 수단은 지시와 강제로 나뉩니다. 지시는 에이전트가 읽고 따르도록 요청하는 수단이며, 규칙 문서가 해당합니다. 강제는 에이전트의 판단과 관계없이 도구가 동작을 허용하거나 막는 수단이며, 권한 규칙(Permission Rule)과 훅(Hook)이 해당합니다.

Claude Code 문서는 권한 규칙을 모델이 아니라 Claude Code가 적용한다고 설명합니다. 프롬프트나 CLAUDE.md의 지시는 에이전트가 시도하는 동작에 영향을 주지만, 허용되는 동작 자체는 정하지 않습니다. 훅은 정해진 시점에 실행되는 셸 명령이며, 에이전트의 판단과 관계없이 적용됩니다(Anthropic, 2026a).

표 4-3의 기준은 규칙을 어겼을 때의 결과입니다. 어겼을 때 다시 작업하면 되는 규칙은 지시로 충분합니다. 원본 자료의 손상이나 외부 발송처럼 되돌리기 어려운 결과를 낳는 규칙은 강제 수단으로 처리합니다.

주간 보고서 하네스의 구현

Chapter 1의 주간 보고서 예제는 Claude Code 파일로 구현되어 있습니다. 실행 자료는 저장소의 examples/ch01-01/ 폴더에 있습니다. 표 4-4는 표 1-2의 설정이 어느 파일에 구현되었는지 보여 줍니다.

다음은 권한 설정 파일의 내용입니다. 원본 자료와 검사 스크립트, 규칙 문서의 수정을 금지해서, 에이전트가 검증 기준 자체를 변경하지 못하게 합니다.

{
  "permissions": {
    "allow": [
      "Read(./data/**)",
      "Read(./output/**)",
      "Edit(./output/**)",
      "Bash(python verify_counts.py)",
      "Bash(python3 verify_counts.py)"
    ],
    "deny": [
      "Edit(./data/**)",
      "Edit(./verify_counts.py)",
      "Edit(./CLAUDE.md)",
      "Edit(./.claude/**)",
      "WebFetch",
      "WebSearch"
    ]
  }
}

도구만 연결하면 에이전트가 된다는 의견이 있습니다. 도구만 연결된 에이전트는 작업을 수행할 수는 있지만, 원본 자료를 변경하지 않았는지, 수치가 맞는지 확인할 근거를 남기지 않습니다. 권한, 기록, 검증은 관리자가 결과를 받아들이기 위한 근거입니다.

하네스 설계는 다섯 구성 요소마다 결정을 내리고, 어겼을 때 되돌리기 어려운 규칙을 강제 수단으로 옮기는 일입니다.
