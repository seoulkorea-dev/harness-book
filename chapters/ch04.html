Chapter 4 하네스의 구성 요소

에이전트는 주어진 역할 안에서, 연결된 도구를 사용해, 허용된 권한 범위의 작업을 수행합니다. 하네스의 품질을 정하는 것은 연결한 도구의 수가 아니라, 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소를 모두 정했는지입니다. 그래서 도구만 연결하고 권한, 기록, 검증을 정하지 않으면, 결과를 받아들일 근거가 없습니다. 따라서 관리자는 구성 요소마다 무엇을 결정해야 하는지 알고 있어야 합니다. 이 장에서는 하네스의 다섯 구성 요소와 구성 요소별 결정 항목을 살펴봅니다.

  • 하네스는 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소로 설계합니다.
  • 규칙 문서는 지시이고, 권한 규칙과 훅은 강제입니다.
  • 반드시 지켜야 하는 규칙은 강제 수단으로 처리합니다.

다섯 구성 요소

Chapter 1의 주간 보고서 예제는 다섯 구성 요소로 하네스를 설정했습니다. 역할은 에이전트가 맡는 작업의 범위입니다. 도구는 에이전트가 사용할 수 있는 기능입니다. 권한은 도구로 할 수 있는 동작의 범위입니다. 기록은 다음 작업에 넘길 정보입니다. 검증은 결과를 받아들이기 전에 확인하는 절차입니다.

그림 4-1은 다섯 구성 요소를, 표 4-1은 구성 요소별로 관리자가 정할 결정과 Claude Code의 구현 방법을 보여 줍니다.

Claude Code의 구현 열은 2026년 10월에 확인한 공식 문서 기준입니다. Codex의 구현 방법은 Chapter 9의 제품 단위 비교에서 다룹니다.

지시와 강제

구성 요소를 구현하는 수단은 지시와 강제로 나뉩니다. 지시는 에이전트가 읽고 따르도록 요청하는 수단이며, 규칙 문서가 해당합니다. 강제는 에이전트의 판단과 관계없이 도구가 동작을 허용하거나 막는 수단이며, 권한 규칙과 훅이 해당합니다.

Claude Code 문서는 권한 규칙을 모델이 아니라 Claude Code가 적용한다고 설명합니다. 프롬프트나 CLAUDE.md의 지시는 에이전트가 시도하는 동작에 영향을 주지만, 허용되는 동작 자체는 정하지 않습니다. 훅은 정해진 시점에 실행되는 셸 명령이며, 에이전트의 판단과 관계없이 적용됩니다(Anthropic, 2026).

표 4-2의 기준은 규칙을 어겼을 때의 결과입니다. 어겼을 때 다시 작업하면 되는 규칙은 지시로 충분합니다. 원본 자료의 손상이나 외부 발송처럼 되돌리기 어려운 결과를 낳는 규칙은 강제 수단으로 처리합니다.

주간 보고서 하네스의 구현

Chapter 1의 주간 보고서 예제는 Claude Code 파일로 구현되어 있습니다. 실행 자료는 저장소의 examples/ch01-01/ 폴더에 있습니다. 표 4-3은 표 1-2의 설정이 어느 파일에 구현되었는지 보여 줍니다.

다음은 권한 설정 파일의 내용입니다. 원본 자료와 검사 스크립트, 규칙 문서의 수정을 금지해서, 에이전트가 검증 기준 자체를 변경하지 못하게 합니다.

{
  "permissions": {
    "allow": [
      "Read(./data/**)",
      "Read(./output/**)",
      "Edit(./output/**)",
      "Bash(python verify_counts.py)",
      "Bash(python3 verify_counts.py)"
    ],
    "deny": [
      "Edit(./data/**)",
      "Edit(./verify_counts.py)",
      "Edit(./CLAUDE.md)",
      "Edit(./.claude/**)",
      "WebFetch",
      "WebSearch"
    ]
  }
}

도구만 연결하면 에이전트가 된다는 의견이 있습니다. 도구만 연결된 에이전트는 작업을 수행할 수는 있지만, 원본 자료를 변경하지 않았는지, 수치가 맞는지 확인할 근거를 남기지 않습니다. 권한, 기록, 검증은 관리자가 결과를 받아들이기 위한 근거입니다.

하네스 설계는 다섯 구성 요소마다 결정을 내리고, 어겼을 때 되돌리기 어려운 규칙을 강제 수단으로 옮기는 일입니다.
