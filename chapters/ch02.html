Chapter 2 하네스의 구성 요소

에이전트(Agent)는 주어진 역할 안에서, 연결된 도구를 사용해, 허용된 권한 범위의 작업을 수행합니다. 하네스(Harness)의 품질을 정하는 것은 연결한 도구의 수가 아니라, 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소를 모두 정했는지입니다. 그래서 도구만 연결하고 권한, 기록, 검증을 정하지 않으면, 결과를 받아들일 근거가 없습니다. 따라서 하네스를 설계할 때는 구성 요소마다 무엇을 결정해야 하는지 먼저 알아야 합니다. 이 장에서는 하네스의 다섯 구성 요소와 구성 요소별 결정 항목을 살펴봅니다.

  • 하네스는 역할, 도구, 권한, 기록, 검증의 다섯 구성 요소로 설계합니다.
  • 규칙 문서는 지시이고, 권한 규칙과 훅은 강제입니다.
  • 반드시 지켜야 하는 규칙은 강제 수단으로 처리합니다.

다섯 구성 요소

하네스는 다섯 구성 요소로 설계합니다. 구성 요소마다 정하는 대상이 다릅니다.

  • 역할: 에이전트가 맡는 작업의 범위입니다. 에이전트가 할 작업과 사람이 할 작업의 경계를 정합니다. 경계가 없으면 발송이나 배포처럼 사람이 판단할 일까지 에이전트가 진행할 수 있습니다.
  • 도구: 에이전트가 사용할 수 있는 기능입니다. 도구가 없으면 에이전트는 자료를 읽거나 결과를 만들 수 없습니다. 도구가 너무 많으면 컨텍스트(Context)를 차지합니다(도구 노출 범위).
  • 권한: 도구로 할 수 있는 동작의 범위입니다. 같은 파일 도구라도 읽기만 허용할지, 수정까지 허용할지를 정합니다.
  • 기록: 다음 작업에 넘길 정보입니다. 모델은 요청 사이의 대화를 기억하지 않습니다(Chapter 1). 그래서 세션이 끝난 뒤에도 남아야 할 결정과 진행 상황은 파일로 남깁니다.
  • 검증: 결과를 받아들이기 전에 확인하는 절차입니다. 에이전트의 완료 보고만으로는 결과가 맞는지 알 수 없으므로, 확인 방법을 미리 정합니다.

그림 2-1은 다섯 구성 요소와 Claude Code의 구현 위치를, 표 2-1은 구성 요소별로 정할 결정과 구현 방법을 보여 줍니다. 그림의 지시, 연결, 강제 표시는 지시와 강제에서 설명합니다.

Claude Code의 구현 열은 2026년 10월에 확인한 공식 문서 기준입니다. Codex의 구현 방법은 Chapter 10의 제품 단위 비교에서 다룹니다.

표 2-1의 하위 에이전트(Subagent)는 특정 작업을 맡도록 별도로 정의한 에이전트입니다. MCP(Model Context Protocol)는 외부 시스템의 기능을 에이전트의 도구로 연결하는 규약이며, 이를 구현한 서버를 MCP 서버라고 합니다. 자동 메모리는 Claude Code가 작업 중의 수정 요청과 선호를 스스로 기록하고 다음 세션에 읽는 기능입니다.

도구 노출 범위

도구를 많이 연결할수록 에이전트가 할 수 있는 일은 늘어나지만, 비용도 함께 늘어납니다. Agent SDK 문서에 따르면 내장 도구의 정의는 요청마다 컨텍스트에 들어가고, 도구 정의 하나하나가 컨텍스트 공간을 차지합니다. 문서는 도구를 선별해서 연결하고, 하위 에이전트에는 필요한 최소한의 도구만 지정하라고 안내합니다(Anthropic, 2026b).

Claude Code는 도구 노출을 줄이는 장치를 둡니다. MCP 서버의 도구 정의는 기본적으로 바로 불러오지 않고, 도구 이름과 서버 안내만 컨텍스트에 둔 뒤 필요할 때 불러옵니다. 비용 문서는 gh, aws 같은 명령줄 도구가 도구 목록을 추가하지 않아 MCP 서버보다 컨텍스트를 적게 차지한다고 설명합니다. 사용하지 않는 서버는 끄라고 안내합니다(Anthropic, 2026b).

노출 범위는 권한과 함께 정합니다. 연결된 도구라도 허용 목록에 없는 도구는 실행 전에 확인을 거치고, 금지 목록의 도구는 실행되지 않습니다. 문서에 따르면 읽기 전용 도구는 동시에 실행될 수 있고, 상태를 변경하는 도구는 충돌을 막기 위해 차례로 실행됩니다. 그림 2-2는 연결된 도구가 권한 규칙(Permission Rule)을 거쳐 이 작업에 노출되는 구조를 보여 줍니다.

도구 노출 범위에서 정할 것은 세 가지입니다.

  • 작업에 연결할 도구: 작업 단위마다 필요한 도구만 연결합니다.
  • 읽기와 수정의 구분: 조회만 필요한 작업에는 읽기 도구만 허용합니다.
  • 하위 에이전트의 도구: 하위 에이전트에는 맡긴 작업에 필요한 최소한의 도구만 지정합니다.

지시와 강제

구성 요소를 구현하는 수단은 지시와 강제로 나뉩니다. 지시는 에이전트가 읽고 따르도록 요청하는 수단이며, 규칙 문서가 해당합니다. 강제는 에이전트의 판단과 관계없이 도구가 동작을 허용하거나 막는 수단이며, 권한 규칙과 훅(Hook)이 해당합니다.

Claude Code 문서는 권한 규칙을 모델이 아니라 Claude Code가 적용한다고 설명합니다. 프롬프트나 CLAUDE.md의 지시는 에이전트가 시도하는 동작에 영향을 주지만, 허용되는 동작 자체는 정하지 않습니다. 훅은 정해진 시점에 실행되는 셸 명령이며, 에이전트의 판단과 관계없이 적용됩니다(Anthropic, 2026a).

표 2-2의 기준은 규칙을 어겼을 때의 결과입니다. 어겼을 때 다시 작업하면 되는 규칙은 지시로 충분합니다. 원본 자료의 손상이나 외부 발송처럼 되돌리기 어려운 결과를 낳는 규칙은 강제 수단으로 처리합니다.

도구만 연결하면 에이전트가 된다는 의견이 있습니다. 도구만 연결된 에이전트는 작업을 수행할 수는 있지만, 원본 자료를 변경하지 않았는지, 수치가 맞는지 확인할 근거를 남기지 않습니다. 권한, 기록, 검증은 사용자가 결과를 받아들이기 위한 근거입니다.

하네스 설계는 다섯 구성 요소마다 결정을 내리고, 어겼을 때 되돌리기 어려운 규칙을 강제 수단으로 옮기는 일입니다.
