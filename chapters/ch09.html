Chapter 9 제품 단위 비교: Codex와 Claude Code의 하네스

Codex와 Claude Code는 모두 규칙 문서, 권한, 격리, 설정 파일로 하네스(Harness)를 구성하지만, 구성 요소마다 구현 방식이 다릅니다. 제품 선택을 정하는 것은 어느 제품의 모델이 우수한지가 아니라, 조직이 운영하려는 하네스를 각 제품이 어떤 방식으로 구현하는지입니다. 그래서 모델 성능만으로 제품을 선택하면, 운영 중에 권한 정책이나 규칙 문서 구성이 조직의 방식과 맞지 않는 문제가 드러납니다. 따라서 관리자는 하네스 구성 요소 단위로 두 제품을 비교해야 합니다. 이 장에서는 규칙 문서, 권한, 격리, 설정 파일 기준으로 두 제품의 구현 방식을 살펴봅니다.

  • 제품은 회사가 아니라 하네스 구성 요소 단위로 비교합니다.
  • 두 제품 모두 지시하는 규칙 문서와 강제하는 권한, 격리 계층을 갖추고 있습니다.
  • 같은 정책도 제품마다 설정 위치와 형식이 다릅니다.

비교 기준

이 장의 비교는 2026년 10월 4일에 확인한 두 제품의 공식 문서 기준입니다. 두 제품 모두 기능이 자주 갱신되므로, 도입을 결정하기 전에 최신 문서를 다시 확인해야 합니다. 비교 기준은 Chapter 4에서 정의한 구성 요소 가운데 제품의 구현 방식이 다른 네 가지입니다. 표 9-1은 기준별 비교 결과입니다.

규칙 문서 비교

Claude Code는 CLAUDE.md를 세션마다 읽습니다. 조직, 사용자, 프로젝트, 개인의 네 범위에 문서를 둘 수 있으며, 상위 디렉터리부터 작업 디렉터리까지의 문서를 모두 이어서 읽습니다. 저장소에 CLAUDE.md가 없고 AGENTS.md만 있으면 AGENTS.md를 읽습니다(Anthropic, 2026).

Codex는 작업을 시작하기 전에 AGENTS.md를 읽습니다. 전역 범위의 ~/.codex/AGENTS.md와 저장소 루트, 하위 디렉터리의 AGENTS.md를 차례로 읽습니다. 같은 디렉터리에 AGENTS.override.md가 있으면 AGENTS.md 대신 그 파일을 읽습니다(OpenAI, 2026).

두 제품을 함께 사용하는 조직은 AGENTS.md를 공통 규칙 문서로 둘 수 있습니다. Claude Code에서 별도 지침이 필요하면, CLAUDE.md에서 AGENTS.md를 불러오고 그 아래에 Claude Code 전용 지침을 추가합니다.

권한과 격리 비교

Claude Code는 도구별 권한 규칙(Permission Rule)으로 동작을 통제합니다. 규칙에 일치하지 않는 동작은 권한 모드(Permission Mode)가 처리합니다. 권한 모드는 default, acceptEdits, plan, auto, dontAsk, bypassPermissions의 여섯 가지입니다. 샌드박스(Sandbox)는 셸 명령의 파일 시스템과 네트워크 접근을 제한하는 별도 계층이며, 설정으로 활성화합니다(Anthropic, 2026).

Codex는 승인 정책(Approval Policy)과 샌드박스의 두 계층으로 통제합니다. 승인 정책은 동작 전에 멈추고 확인하는 시점을 정하고, 샌드박스는 명령이 접근할 수 있는 파일과 네트워크를 정합니다. 로컬 실행의 기본값은 네트워크 접근 차단, 작업 공간 안의 수정만 허용입니다. 기본 제공 권한 프로필은 읽기 전용, 작업 공간 수정 허용, 제한 없음의 세 가지입니다(OpenAI, 2026).

두 제품의 차이는 출발점에 있습니다. Claude Code는 도구별 규칙을 세밀하게 지정하는 방식에서 출발하고, 격리는 추가로 설정합니다. Codex는 운영 체제 수준의 격리를 기본으로 적용하고, 승인 정책으로 확인 시점을 조정합니다.

같은 정책의 두 제품 설정

다음 정책을 두 제품에 설정하는 예입니다. 작업 폴더 밖의 파일은 수정하지 않고, 네트워크에 접근하지 않으며, 원격 저장소에 push하지 않습니다.

Claude Code 설정(.claude/settings.json)

{
  "permissions": {
    "deny": ["Bash(git push *)", "WebFetch", "WebSearch"]
  },
  "sandbox": {
    "enabled": true
  }
}

작업 폴더 밖의 파일 수정은 Claude Code의 기본 동작이 작업 디렉터리로 제한하고, 샌드박스가 셸 명령의 접근을 운영 체제 수준에서 제한합니다. push 금지는 deny 규칙으로 지정합니다.

Codex 설정(~/.codex/config.toml)

sandbox_mode = "workspace-write"
approval_policy = "on-request"

[sandbox_workspace_write]
network_access = false

workspace-write 샌드박스가 작업 공간 밖의 수정을 막고, network_access 설정이 네트워크 접근을 차단합니다. push는 네트워크 접근이 필요하므로 샌드박스 안에서 실행되지 않으며, 승인 정책에 따라 확인 요청으로 넘어갑니다.

이 설정에서 Codex는 push를 금지하지 않고, 실행 전에 확인을 요청합니다. Claude Code의 deny 규칙처럼 금지하려면 규칙 파일(~/.codex/rules/default.rules)에 forbidden 규칙을 추가합니다.

prefix_rule(
    pattern = ["git", "push"],
    decision = "forbidden",
)
버전 주석 (2026년 10월) Codex 문서는 이전에 사용하던 untrusted 승인 정책을 더 이상 지원하지 않는다고 밝힙니다. Claude Code 문서는 시작 권한 모드가 실행 방식에 따라 다르다고 안내합니다. v2.1.283 이상의 대화형 터미널과 VS Code 세션은 모든 요금제에서 auto 모드로 시작합니다. Codex 문서는 규칙 기능을 실험 단계로 안내합니다. 도입 시점의 문서에서 기본값을 확인합니다.

더 좋은 모델을 사용하는 제품을 선택하면 된다는 의견이 있습니다. 모델은 두 제품 모두 갱신되며, 운영 중에 매일 영향을 주는 것은 권한 정책, 규칙 문서 구성, 격리 방식입니다. 조직의 보안 정책이 격리를 기본으로 요구하는지, 도구별 규칙을 세밀하게 관리하려는지가 선택 기준입니다.

제품 비교는 조직이 운영하려는 하네스를 기준으로, 구성 요소마다 두 제품의 구현 방식을 대조하는 일입니다.
