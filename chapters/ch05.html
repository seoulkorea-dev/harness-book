Chapter 5 착수: 맡길 업무 선정과 작업 단위 분할

에이전트는 맡은 업무를 한 세션 안에서 처리하려고 하며, 세션이 끝나면 진행 중이던 상태를 기억하지 못합니다. 위임의 성패를 정하는 것은 업무의 크기가 아니라, 업무를 결과를 확인할 수 있는 단위로 나누었는지입니다. 그래서 한 번에 큰 업무를 맡기면, 중간에 멈춘 작업과 완료되지 않은 기능이 기록 없이 남습니다. 따라서 착수 전에 맡길 업무를 선정하고, 완료 기준을 갖춘 작업 단위로 분할해야 합니다. 이 장에서는 맡길 업무의 선정 기준과 작업 단위 분할 방법을 다룹니다.

  • 맡길 업무는 결과 확인, 자료 접근, 되돌림 가능 여부로 선정합니다.
  • 작업 단위는 한 세션에 끝나고 완료 여부를 확인할 수 있는 크기로 나눕니다.
  • 작업 단위 목록은 완료 기준과 상태를 함께 기록합니다.

맡길 업무의 선정

모든 업무가 에이전트에 맡기기에 적합하지는 않습니다. 이 책은 맡길 업무를 네 가지 기준으로 선정합니다. 표 5-1은 기준별 확인 질문과 기준을 충족하지 못할 때의 처리 방법입니다.

네 기준을 모두 충족하는 업무부터 맡깁니다. 일부 기준을 충족하지 않는 업무도 위임 대상에서 제외할 필요는 없습니다. 충족하지 못한 부분을 사람이 맡도록 업무를 나누면 됩니다.

작업 단위 분할

Anthropic은 여러 세션에 걸쳐 웹 애플리케이션을 개발하는 실험에서 에이전트의 실패 양상 두 가지를 보고했습니다(Young, 2025). 첫째, 에이전트는 애플리케이션 전체를 한 번에 구현하려고 했습니다. 구현 도중 컨텍스트가 소진되어, 다음 세션은 반쯤 구현되고 기록되지 않은 기능에서 시작했습니다. 둘째, 일부 기능이 구현된 뒤 시작한 세션은 진행된 내용을 보고 프로젝트 전체가 완료되었다고 판단했습니다.

Anthropic의 해결 방법은 작업 단위 분할이었습니다. 첫 세션에서 요구 사항을 200개가 넘는 기능 목록으로 작성하고, 모든 기능을 "실패" 상태로 표시했습니다. 이후 세션은 한 번에 기능 하나만 작업했습니다. Anthropic은 이 점진적 방식이 에이전트가 한 번에 너무 많은 작업을 시도하는 문제를 해결하는 데 결정적이었다고 밝혔습니다(Young, 2025).

작업 단위의 크기 기준은 두 가지입니다. 한 세션 안에 끝나야 하고, 완료 여부를 확인할 수 있어야 합니다. 그림 5-1은 업무를 선정하고 작업 단위로 분할해 실행하는 순서입니다.

변경 요청의 작업 단위 분할 예제

Chapter 2의 변경 요청 영향 검토 예제에서 다룬 CR-07을 수용하기로 했다고 가정합니다. 정산 요청 화면에 프로젝트 코드 선택 항목을 추가하는 변경입니다. 표 5-2는 이 변경을 작업 단위로 분할한 결과입니다.

첫 번째 작업 단위는 연동 규격이 없어 다른 조직과의 합의가 필요하므로 PM이 맡습니다. 나머지 작업 단위는 합의 결과를 입력으로 받아 에이전트가 수행합니다. 마지막 작업 단위는 에이전트가 작성하지만, 통합 테스트의 범위를 정하는 판단이므로 PM이 승인합니다.

작업 단위 목록은 에이전트가 읽고 상태를 갱신할 수 있는 파일로 저장합니다. Anthropic은 기능 목록을 JSON 형식으로 저장했고, 에이전트가 상태 항목만 수정하도록 지시했습니다. 모델이 Markdown 파일보다 JSON 파일을 부적절하게 변경하거나 덮어쓰는 일이 적었기 때문입니다(Young, 2025).

[
  {
    "id": "CR-07-2",
    "작업": "데이터 모델에 프로젝트 코드 항목 추가",
    "완료 기준": "정산 요청 데이터에 항목 추가, 기존 데이터 유지",
    "확인 방법": "데이터 변환 시험 통과",
    "통과": false
  },
  {
    "id": "CR-07-3",
    "작업": "정산 요청 화면에 선택 항목 추가",
    "완료 기준": "화면에서 프로젝트 코드 선택 가능",
    "확인 방법": "화면 시험 통과",
    "통과": false
  }
]

큰 업무를 한 번에 맡기는 편이 효율적이라는 의견이 있습니다. 한 번에 맡긴 업무가 실패하면, 관리자는 어느 부분에서 실패했는지 확인할 단위가 없습니다. 작업 단위로 나누면 실패한 단위만 다시 작업합니다.

위임은 업무를 결과를 확인할 수 있는 단위로 나누는 일에서 시작합니다.
