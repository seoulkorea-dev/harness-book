Chapter 3 컨텍스트 엔지니어링: 에이전트가 읽는 정보 설계

에이전트(Agent)는 작업을 시작할 때 규칙 문서와 요청, 작업 중에 읽은 파일과 도구 결과를 근거로 판단합니다. 결과를 정하는 것은 요청 문장의 완성도가 아니라, 에이전트가 판단하는 시점에 무엇을 읽고 있는지입니다. 그래서 필요한 자료가 없거나 오래된 자료가 남아 있으면, 같은 요청에도 근거가 다른 결과가 나옵니다. 따라서 에이전트가 읽을 자료를 선별하고 최신 상태로 유지하는 일은 관리자의 업무입니다. 이 장에서는 에이전트가 읽는 정보의 종류와 규칙 문서 작성 방법을 익힙니다.

  • 컨텍스트는 한정된 자원이므로 필요한 자료를 선별해서 제공합니다.
  • 에이전트가 읽는 정보는 상시 규칙, 필요할 때 읽는 문서, 작업 입력, 작업 중 생성 정보로 나뉩니다.
  • 규칙 문서는 짧게 유지하고, 같은 실수가 반복될 때 항목을 추가합니다.

컨텍스트는 한정된 자원

컨텍스트는 모델이 응답을 생성할 때 입력되는 정보 전체이며, 모델은 이 정보를 토큰(Token) 단위로 처리합니다. Anthropic은 컨텍스트를 한정된 자원으로 설명합니다. 토큰이 늘어날수록 모델이 그 안에서 정보를 정확히 찾는 능력이 떨어지는 현상이 있기 때문입니다(Rajasekaran 외, 2025).

자료를 많이 제공할수록 결과가 나아진다는 의견이 있습니다. 컨텍스트가 한정된 자원이라면, 관련 없는 자료는 관련 있는 자료가 차지할 자리를 줄입니다. 관리자가 정할 것은 자료의 양이 아니라, 작업마다 어떤 자료를 읽게 할지입니다.

에이전트가 읽는 정보의 종류

에이전트가 읽는 정보는 읽히는 시점에 따라 네 가지로 나뉩니다. 상시 규칙은 세션이 시작될 때마다 읽히는 문서입니다. 필요할 때 읽는 문서는 특정 작업이나 특정 파일을 다룰 때만 읽힙니다. 작업 입력은 관리자가 요청과 함께 제공하는 자료입니다. 작업 중 생성 정보는 에이전트가 파일을 열거나 도구를 실행해서 얻은 결과입니다. 그림 3-1은 네 종류를, 표 3-1은 종류별 예와 관리 방법을 보여 줍니다.

OpenAI는 큰 AGENTS.md 하나에 모든 내용을 담는 방식이 실패했다고 밝혔습니다. 이후 약 100줄의 짧은 AGENTS.md가 세부 문서의 위치를 안내하는 방식으로 전환했습니다(Lopopolo, 2026). 상시 규칙에는 모든 작업에 필요한 내용만 두고, 나머지는 필요할 때 읽는 문서로 분리하는 구성입니다.

규칙 문서 작성

규칙 문서는 에이전트가 세션마다 읽는 프로젝트 지침입니다. Claude Code는 CLAUDE.md를, Codex는 AGENTS.md를 읽습니다. Claude Code 문서는 CLAUDE.md 작성 기준을 다음과 같이 안내합니다(Anthropic, 2026).

  • 확인할 수 있을 만큼 구체적으로: "코드를 정리해 줘" 대신 "API 처리 파일은 src/api/handlers/에 둔다"처럼 작성합니다.
  • 짧게: 파일 하나를 200줄 이내로 유지합니다. 문서가 길수록 컨텍스트를 더 차지하고 지침 준수율이 낮아집니다.
  • 일관되게: 두 지침이 서로 모순되면 에이전트가 둘 중 하나를 임의로 따를 수 있습니다.
  • 분리: 여러 단계로 이루어진 절차나 일부 파일에만 해당하는 지침은 Skill이나 경로별 규칙으로 분리합니다. Skill은 필요할 때만 읽히는 지침과 자료의 묶음입니다.

다음은 Chapter 1과 Chapter 2에서 다룬 가상 프로젝트, 경비 정산 시스템 개편의 규칙 문서 예입니다. 모든 작업에 해당하는 규칙만 담고, 세부 문서는 위치만 안내합니다.

# 경비 정산 시스템 개편 프로젝트

## 프로젝트
- 목표: 경비 정산 요청, 승인, 지급 화면 개편. 통합 테스트 시작일 2026-10-19
- 작업 번호는 EXP-숫자, 변경 요청 번호는 CR-숫자 형식

## 작업 규칙
- 작업 하나를 끝내면 작업 번호를 포함한 커밋을 남긴다
- 완료 보고에는 실행한 검사 명령과 출력 원문을 포함한다
- 자료에 근거가 없는 수치는 "확인 필요"로 표시한다

## 금지
- data/ 폴더의 원본 자료는 수정하지 않는다
- 고객사에 보내는 문서는 초안까지만 작성한다

## 세부 문서 위치
- 화면 설계: docs/screens.md
- 변경 요청 처리 절차: docs/change-request.md
- 결정 기록: DECISIONS.md

이 책의 저장소도 같은 구성을 사용합니다. 저장소 루트의 CLAUDE.md, 문체 규칙인 STYLE.md, 결정 기록인 DECISIONS.md를 작가와 두 에이전트가 작업 전에 읽습니다.

규칙 문서의 관리

규칙 문서는 한 번 작성하고 끝나는 문서가 아닙니다. Claude Code 문서는 CLAUDE.md에 항목을 추가할 시점으로 네 가지를 제시합니다(Anthropic, 2026).

  • 에이전트가 같은 실수를 두 번째로 반복했을 때
  • 코드 리뷰에서 에이전트가 알았어야 할 내용이 지적되었을 때
  • 지난 세션에 입력한 정정 내용을 다시 입력하고 있을 때
  • 새로 합류한 팀원에게도 같은 설명이 필요할 때

규칙 문서는 지시일 뿐 강제가 아닙니다. Claude Code 문서는 CLAUDE.md를 강제 설정이 아닌 컨텍스트로 다룬다고 설명합니다. 반드시 막아야 하는 동작은 훅(Hook)으로 처리하라고 안내합니다(Anthropic, 2026). 훅은 정해진 시점에 자동으로 실행되는 셸 명령입니다. 지시로 충분한 규칙과 강제가 필요한 규칙의 구분은 Chapter 4의 지시와 강제에서 다룹니다.

에이전트가 읽는 정보의 설계는 상시 규칙을 짧게 유지하고, 나머지를 필요할 때 읽도록 분리하는 일에서 시작합니다.
