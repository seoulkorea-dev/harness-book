설명할 수 있는 것 세 가지
1. 에이전트의 완료 보고는 만든 쪽의 판단이라, 검사 출력 같은 직접 확인 가능한 증거를 근거로 삼아야 한다(Claude Code 사례: 단위 테스트는 통과했는데 기능은 안 돌았다는 이야기까지는 말할 수 있음. 왜 그랬는지는 막연함).
2. 완료 기준은 작업 전에 "통과/실패가 갈리는 검사"로 바꿔 둔다(표 7-2). 코드로 못 가르는 기준은 기준표와 예시 답안으로 LLM에게 채점시키고, 되돌리기 어려운 것만 사람이 본다(세 가지 채점 방법).
3. 검사 스크립트는 건수를 출력하고, 0건 실행도 실패로 치며, 에이전트가 시험과 스크립트를 못 고치게 막는다. 다만 코드 내부 동작과 "자동 검사/출력 확인/독립 검수"와 "코드/LLM/사람 채점"의 대응은 자신 있게 설명하지 못함(#6, #10, #16 때문).
