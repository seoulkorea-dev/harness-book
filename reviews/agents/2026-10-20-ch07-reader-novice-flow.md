## C. 이 장을 읽고 나서 설명할 수 있는 것 세 가지
1. 완료 보고는 일한 쪽의 판단이라 근거가 못 되므로, 작업 전에 완료 기준을 통과나 실패로 갈리는 검사로 바꿔 두고 검사 출력 원문으로 판정한다. 근거 사례는 단위 테스트는 통과했는데 기능 전체는 동작하지 않던 에이전트 실험이다.
2. 기준 항목마다 자동 검사(스크립트), 출력 확인(사용자), 독립 검수(만들지 않은 쪽) 중 하나를 고른다. 판단이 필요한 기준은 기준표와 예시 답안, 통과 조건으로 LLM이나 사람이 채점하고, 사람은 되돌리기 어려운 결정에 둔다.
3. CR에서는 check.py가 폴더별 실행 건수와 실패 건수를 출력하고, 실행 0건도 실패로 친다. 시험 파일의 수정은 금지 규칙으로 막고 git status로 다시 확인한다. 훅과 Stop 훅의 세부 역할은 확신 있게 설명하지 못한다(위 #3 때문).
