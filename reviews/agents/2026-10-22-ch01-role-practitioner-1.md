## 새 첫머리 방향 의견
꼭 들어갈 것
1. "정산 화면 오류를 고쳐 줘"는 실제 순서로: 하네스가 시스템 프롬프트, 규칙 문서, 도구 정의, 요청을 모아 넘김 → 모델이 검색과 읽기를 요청하고 하네스가 실행해 돌려줌 → 모델이 수정 내용을 만들면 하네스가 권한을 확인하고 파일에 적용 → 모델이 테스트 실행을 요청하면 하네스가 실행하고 출력을 돌려줌 → 실패하면 반복, 끝내려 하면 검사가 완료 기준 확인. 수정 코드를 쓰는 것은 모델이고 하네스는 적용한다.
2. 모델이 요청해서 하는 실행과 하네스가 강제하는 실행(훅, 금지 규칙)의 구분.
3. "위험한 변경 차단"은 구체적 예(.env 읽기, 작업 폴더 밖 쓰기, git push)와 "규칙에 맞으면 막음"으로.
4. "사람 확인"은 권한 규칙의 확인 요청, 곧 승인 지점과 연결.
5. "예외 상황 통제"가 오류 처리로만 읽히지 않게, 통제는 정상 흐름에서도 매번 작동함을 밝힘.
6. "실행 환경 설계"에 피드백 장치(테스트, 린터, 로그)를 넣음.
7. 두 가지를 다섯 구성 요소와 한 문장으로 이음.
8. 이름의 유래는 "이 이름을 처음 쓴 글"이 아니라 "이름이 널리 알려진 계기가 된 글"로(그 전에도 하네스라는 말이 쓰임).
빼야 할 것
1. "모델은 판단, 하네스는 실행"을 예외 없는 규칙처럼 쓰지 않음(서버 도구 등).
2. 하네스가 결과가 맞는지 직접 판단하는 것처럼 쓰지 않음(팀이 정한 검사를 실행할 뿐).
3. 첫머리에 ReAct, 워크플로, 결합형 비교를 넣지 않음.
