# 부록 편집 검토(chief-editor)

## 1. 총평과 판정

**판정: 지금 상태로는 병합 불가입니다. 아래 필수 지적을 반영하면 병합할 수 있습니다.**

부록 두 쪽을 처음부터 끝까지 독자 순서로 읽었습니다. 실습은 준비부터 막혔을 때까지, 실습 1~6을 명령 단위로 따라가며 읽었습니다. 용어 풀이는 항목마다 정의를 Chapter 1~11, 시작하며, BOOK_SPEC 4·5절과 대조했습니다. 대조한 실습 자료는 reference의 CLAUDE.example.md, settings.example.json, tasks.example.json과 docs/CR.md입니다.

**가장 큰 문제 셋**
1. **실습을 순서대로 따라 하면 멈추는 곳이 있습니다.**
   - 터미널을 여는 방법이 설치 명령보다 뒤에 나옵니다(지적 3~5).
   - 확인 화면을 보려면 권한 모드를 default로 시작해야 한다는 안내가, 이미 Claude Code를 시작한 뒤인 실습 2의 6단계에 나옵니다(지적 6, 14, 15, 23).
   - 실습 4 확인 방법은 둘째 요청 뒤 /exit로 종료하라고 하는데, 셋째 요청(reviewer)이 아직 남아 있습니다(지적 24).
   - 실습 5의 3~5단계는 번호 없는 문단에 들어 있습니다. 그 안의 "확인 요청을 거절하고 에이전트에게 물어 확인"은 다시 commit하는 방법이 없는 경로이고, 에이전트의 자기 보고에 기대는 방법이라 Chapter 7과도 맞지 않습니다(지적 28).
2. **확인 방법이 실제 결과를 증명하지 못하는 곳이 있습니다.**
   - 실습 3: CLAUDE.md가 이미 있어 에이전트가 시도 자체를 하지 않을 수 있습니다. 그러면 "금지 규칙으로 거부되었다는 메시지"가 나오지 않아, 금지 규칙이 작동했는지 알 수 없습니다(지적 18).
   - 실습 4: 훅이 실패를 알리면 에이전트가 tests/의 시험을 고칠 수 있는데, 확인은 git diff expense/만 봅니다(지적 22, 24).
   - 실습 5: git diff HEAD -- tasks.json은 commit이 끝난 뒤에는 아무것도 보여 주지 않습니다(지적 27, 플레이북 14장).
   - 실습 3: .claude/를 실습 2에서 만들었다고 잘못 적었습니다(지적 19).
3. **용어 풀이에서 비슷한 용어가 정의로 구별되지 않고, 정의 안에 풀이에 없는 용어가 쓰입니다.**
   - 구별이 안 되는 짝:
     - 장치와 실행 장치(지적 50)
     - 세 설계 층의 "층"과 실행 장치·설정의 "층"(지적 43)
     - 영역과 지시와 강제(지적 48)
     - 검증과 검증 기준(지적 37)
     - 승인 정책의 "에이전트 도구"와 에이전트 제품(지적 45)
   - 정의 안에 쓰였지만 풀이에 항목이 없는 용어: 세션 기록, 권한 설정, 시스템 프롬프트, 단위 테스트, Agent SDK, 작업 단위 목록, 통과 값, 변경 요청 사항(지적 39, 40, 41, 44, 46, 49, 52, 56). 핵심 개념인 외부 실행 환경도 빠졌습니다(지적 47).
   - 훅 항목에는 BOOK_SPEC 5절의 한계("실행되지 않거나 실패하면 막지 못함")가 없습니다(지적 55).
