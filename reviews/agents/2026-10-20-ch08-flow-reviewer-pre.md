# Chapter 8 논지 사슬(2026-10-20, 개정 전 원고 통독, ch08-write)
장의 주장: 작업이 이어지는지를 정하는 것은 대화 이력의 길이가 아니라, 결정과 진행 상황이 에이전트가 읽을 수 있는 문서로 남아 있는지입니다.

# 개정 명세에 넣을 제안

## 1. 절 순서(앵커 유지: kinds, decisions, handover, principle. 다른 장이 참조)
장 첫 문단과 요약 → session(왜 문서인가) → kinds → decisions → handover → logs → example(CR 적용, 새 절) → fail → check → principle.

순서의 이유: session이 "문서가 필요하다"를 보이고, kinds가 무엇을 남길지, decisions와 handover가 사람이 쓰는 두 문서를 풀고, logs가 "사람이 쓰지 않아도 남는 기록"으로 확장하며, example이 전부를 CR에 한 번에 채움. 한 가지 예외로 Chapter 3 표의 "기록, 결정, 진행, 실행 로그"와 Chapter 11의 링크(ch08#kinds, #decisions)는 앵커가 그대로이므로 유지됨.

## 2. 절 첫 문단 제안(왜 → 무엇 → 어떻게 → 근거)
- 장 첫 문단: 작동(새 세션은 새 컨텍스트에서 시작하고 이전 대화를 모름) → 한계(대화에서만 합의한 내용은 세션이 끝나거나 압축되면 사라짐) → 결과(같은 논의와 실수 반복) → 행동(결정, 진행, 규칙을 저장소 문서로 기록) → "기록의 종류, 결정 기록의 형식, 인계 메모, 자동으로 남는 실행 로그를 CR에 적용해 살펴봅니다."(범위 동사).
- session: 왜(작업 상태가 세션 사이에 이어지지 않아 Claude Code 실험에서 문제가 됨) → 무엇(이어 가는 것은 문서와 커밋) → 근거(Young, Anthropic 2026a, Lopopolo) → 반론 답(대화 이력은 세션을 넘지 못하고 압축에도 사라짐, 링크). 끝 문장 "그러면 어떤 문서를 남길지가 다음 절입니다"로 kinds와 연결.
- kinds: 왜(남길 정보의 성격이 달라 질문이 셋: 왜 그렇게 정했나, 어디까지 했나, 늘 무엇을 지키나) → 무엇(이 책은 결정 기록, 진행 기록, 규칙 문서의 세 종류로 정리하고, 인계 메모는 이 셋을 새 세션이 읽도록 묶는 문서) → 어떻게(표 8-1, 갱신 시점) → 근거(Young, 진행 기록 문장 바로 뒤).
- decisions: 왜(결정을 바꿨을 때 이전 결정이 남지 않으면 다음 세션이 폐기된 결정으로 돌아감) → 무엇(이 책이 정리한 형식) → 어떻게(삭제하지 않고 대체로 적음) → 근거(이 책 저장소의 결정 기록 한 문장).
- handover: 왜(규칙 문서는 모든 세션에 같고, 현재 상태와 다음 작업은 세션마다 다르므로 새 세션이 어디까지 했는지 알 수 없음) → 무엇(이 책은 인계 메모를 현재 상태를 한 문서로 묶어 넘기는 것으로 정리) → 어떻게(다섯 항목) → 근거(CR 적용 절의 HANDOFF.md).
- logs: 왜(사람이 쓴 문서만으로는 에이전트가 실제로 한 일을 확인할 수 없음) → 무엇(이 책은 하네스가 자동으로 남기는 기록을 실행 로그로 정리) → 어떻게(네 가지: 세션 기록, 실행 결과, 훅 기록, 조직 지표, 정할 것 세 가지) → 근거(Anthropic 2026b, Chapter 7 증거 링크).
- example(CR 적용): 왜(CR을 두 세션에 나눠 구현할 때 세션 사이 기록이 하는 일을 보이기 위해) → 무엇(작업 번호는 Chapter 6 표 6-4의 작업 1~5. 세션 1이 작업 2, 3을 끝내고 세션 2가 작업 4부터 시작하는 상황) → 어떻게(표: 세션 1이 남긴 결정 기록, 진행 기록, 인계 메모 내용과 세션 2의 읽는 순서) → 근거(예제 파일 CLAUDE.example.md의 읽는 순서, 실습 6 링크).
  - 표 내용은 예제 규칙 문서와 같게: 읽는 순서 CR.md, DECISIONS.md, tasks.json, HANDOFF.md. 에이전트가 수정할 수 있는 파일과 수정하지 않는 파일(DECISIONS.md는 사람이 갱신)을 밝힘. D-012, D-015 예시도 여기서 보임(실습 폴더에는 D-012만 있다는 말 포함).
  - HANDOFF.md 다섯 항목의 CR 값 예: 현재 상태(작업 2, 3 완료), 읽을 문서, 미결정, 다음 작업(작업 4), 확인 명령(python check.py).
- 확인 방법, 원칙, 점검 질문: 11번, 22번, 23번대로 로그 행과 질문을 추가.
