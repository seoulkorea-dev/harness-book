## 개정 전 항목 확인
- 읽기 중단 4건(4, 7, 8, 13)은 풀렸습니다. 21번도 읽기 중단이었는데 함께 풀렸습니다. 18번은 위 1번(느려짐)으로 낮아졌습니다.
  - 4번(승인 지점): 정의와 화면 표시("Claude Code의 대화 화면에 실행할 동작이 표시되고, 승인자가 승인하거나 거절")가 생겼습니다. Anthropic 인용과 "그래서 규칙으로 강제"의 연결도 생겼습니다.
  - 7번(권한 규칙): 2장 링크로 넘기고, 이 장은 "구체성은 순서를 바꾸지 않는다"와 배치 기준만 더합니다. 링크로 충분합니다.
  - 8번(그림 9-1): 2×2 표가 사라지고 규칙 배치와 격리 보완이라는 하나의 메시지가 되었습니다(남은 걸림은 위 4번).
  - 13번(git -C . push): "같은 push를 다른 형태로 작성한 명령"과 "글자만 대조"가 한 문단에 풀렸습니다.
  - 21번(/usage): Session 항목과 API 사용자용, 정가 기준 추정치가 정리되었습니다. 이 책이 어느 쪽 사용자를 기준으로 하는지는 "구독 요금제 사용자는 같은 화면에서 요금제 사용량"이라는 한 줄로 갈립니다. 그래서 읽기는 계속할 수 있습니다. "추정치와 청구액이 다르면 어떻게 하라"는 그림 9-2의 "요금 화면에서 확인" 한 줄로 풀렸습니다.

## 이 장을 읽고 나서 설명할 수 있는 것 세 가지
1. 승인 지점은 되돌리기 어려운 동작에만 둡니다. 사람이 시점을 정할 동작은 확인 요청(commit), 사람이 직접 할 동작은 금지(push)입니다. 파일 수정과 검사 실행은 허용해, 모든 동작에 확인을 두면 확인 없이 승인하게 되는 문제를 피합니다.
2. 권한 규칙은 명령 글자만 대조하므로 git -C . push 같은 다른 형태의 명령이나 스크립트를 통한 간접 수정은 막지 못합니다. 그래서 운영 체제가 셸 명령의 파일과 네트워크 접근을 제한하는 샌드박스(기본값은 꺼짐, /sandbox로 켬)로 보완합니다. CR 예제는 샌드박스를 켜지 않은 상태라 이 우회가 열려 있습니다.
3. 비용은 작업 단위, 읽힐 자료의 범위, 지출 한도로 관리하고, 한도에 이르면 사람이 계속 여부를 정합니다. /usage의 Session 항목으로 토큰 사용량을 보며, 금액은 추정치입니다. 샌드박스가 정확히 어떤 원리로 막는지와 권한 모드가 정확히 무엇인지는 이 장만으로 설명하지 못합니다(10장 몫).
