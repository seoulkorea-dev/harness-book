# 그림 3-1 시안 의견(alt-reviewer, 이슈 #47)

## 추천: 시안 B(ㄹ자 두 줄 + 중단), 단 아래 보완 2건을 붙이는 조건

### 이유
- 시안 B는 "검사 스크립트 통과 시"라는 분기를 그림이 직접 보여 줍니다. 검사 스크립트 바로 아래에 검토 대조가 놓이고 "통과 시" 실선 화살표가 있어, 검사를 통과해야 검토로 간다는 순서가 보입니다. 시안 A는 검사 스크립트 → 검토 대조 화살표에 이름이 없어, 점선 되돌림과 비교해도 통과/실패 분기가 덜 분명합니다.
- B는 한 줄 세 단계라 상자가 넓고(폭 280), 부제 글자가 한 줄에 들어갑니다. A는 상자 폭이 206이라 "검토 하위 에이전트, / 읽기 전용"처럼 글자가 두 줄로 쪼개집니다.
- B는 ㄹ자 끝(다음 작업 단위)이 시작(파일 수정) 바로 아래에 오므로, 작업 단위가 반복된다는 점을 그리기 쉽습니다(아래 발견 1).
- 시안 A의 장점은 앞 네 단계가 한 줄이라 "자동 단계 → 검토"가 한눈에 읽히는 것입니다. 단점은 세 번째 줄을 오른쪽에서 왼쪽으로 읽고, 중단 상자가 왼쪽 끝에 떨어져 다음 작업 단위 옆에 있어 두 출구(다음 작업 단위, 중단)가 같은 줄에서 경쟁하는 것입니다. B는 중단을 오른쪽 아래로 빼서 정상 흐름과 분리됩니다.

### 표와 본문 쪽 (그림 밖)
- 표 3-3 "검증 흐름과 중단" 행(ch03.html 45행)은 "파일 수정, 훅의 단위 테스트, 검사 스크립트, commit 확인"만 말하고 검토 대조가 빠져 새 그림과 어긋남. 검토 대조를 검사 스크립트와 commit 확인 사이에 넣어야 함.
