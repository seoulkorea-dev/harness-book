## 총평
1. 권한 부분이 실제보다 단순하다. "금지, 확인, 허용 순서, 처음 일치"만 있고, 어느 규칙에도 맞지 않을 때 권한 모드가 정한다는 점과 PreToolUse 훅이 규칙보다 먼저 작동한다는 점이 빠졌다(research/ch02-sources.md: 훅 → deny → ask → 권한 모드 → allow). 예제가 안전한 이유의 절반(허용 목록 밖 Bash 명령은 기본 모드에서 사람에게 물음)이 설명되지 않는다.
2. 검증이 1장과 이어지지 않는다. 1장은 완료 기준 확인을 Stop 훅으로 설명하고 "훅이 실제로 불렸는지 확인하는 방법은 Chapter 2의 확인 방법"이라고 약속했는데, 2장 예제는 PostToolUse 훅뿐이고 표 2-6에 훅이 실행되었는지 보는 기준이 없다.
3. 강제의 한계를 좁게 쓴다. "확실하게 지켜집니다"와 달리 Edit 금지는 Bash 쓰기(sed -i, python -c, cp)를 막지 못하고, Bash(git push *)는 git -C . push 같은 변형과 일치하지 않는다.
4. 예제 적용이 원리 절에 흩어지고 "예제: …" 절이 없다. 옛 인용 15곳, CR 15곳, 같은 장 링크 3곳.
5. 좋은 점: 가용성과 권한 평가 구분, 이름만 지정한 금지 규칙의 목록 제외, PostToolUse가 편집을 막지 못한다는 설명은 실제와 맞고 유용하다(유지 권장).
