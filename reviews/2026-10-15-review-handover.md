## 2. 책의 현재 방향 (2026-10-15 재시작 결정)

- 독자: 하네스 엔지니어링을 배우려는 대학생과 직장인. 설명은 자세하게, 실행 가능한 실습 포함. 독자를 나타내는 표현은 본문에 쓰지 않음
- 관리자 관점과 관리자 표현은 본문에서 없애고 범용 서술로 씀(이전 원고는 관리자 관점)
- Codex와 Claude의 차이는 인정하되 중요한 내용은 Claude 기준
- 목차: 현재 11장 구조 유지(1 하네스란 무엇인가, 2 구성 요소, 3 하네스로 에이전트 설계하기, 4 요청 설계, 5 정보 설계, 6~9 착수, 검증, 기록과 인계, 위험 관리, 10 제품 비교, 11 작가 사례, 시작하며, 마치며, 부록 용어 풀이)
- 하네스 정의(D-061): 에이전트는 모델과 하네스로 이루어짐. 하네스는 모델을 에이전트로 동작하게 하는 모델 바깥의 실행 장치 전체(루프 실행, 도구 제공, 컨텍스트 관리, 권한, 기록, 검증). 근거는 Claude Code 공식 용어집의 "agentic harness" 항목
- 제목: 「하네스 엔지니어링: 모델을 에이전트로 만드는 설계」, 부제 "프롬프트, 컨텍스트, 하네스로 에이전트 설계하기"(13c05c4, D-069, D-070)
- 3장 예제: 경비 정산 미니 웹 앱에 변경 요청 CR-07(정산 요청 화면에 프로젝트 코드 선택 항목 추가)을 구현하는 에이전트. Python 표준 라이브러리만 사용. 설계서는 7절
- 그림 방침: 직사각형 영역에 구성 요소와 관계를 배치한 해설 그림, 그림마다 해설표. 박스와 화살표를 늘어놓는 그림은 쓰지 않음
- 배경색: --paper #FFFFFF, --panel #F8F8F6, --rule #EAEAE6(D-064)
- 작가 진행 원칙: 부족한 내용은 한 가지씩 묻고 진행

## 4. 검수 방법 (지금까지 사용한 것)

### 4-1. 시작 순서

```
git clone https://github.com/seoulkorea-dev/harness-book.git
cd harness-book
git log --oneline -15
```

먼저 읽을 파일: CLAUDE.md, STYLE.md, NEW_BOOK_PLAYBOOK.md(3장 원고 원칙, 4장 반영 확인), DECISIONS.md(최신 결정까지), BOOK_SPEC.md, reviews/의 마지막 문서, research/의 사실 확인 기록

### 4-2. 검사 명령

```
python3 tools/build.py
git grep -nE -f lint/banned.txt -- index.html chapters appendix   # 출력 없음, exit 1이 정상
python3 lint/check_numbers.py
python3 lint/check_structure.py     # 참고 자료 링크, 장마다 첫 등장 병기(D-041) 포함
python3 lint/check_style.py         # 경고 줄이 있으면 CI 실패
git diff --exit-code -- index.html chapters appendix
python3 -m http.server 8800 &  # 별도 실행 뒤
python3 tools/verify_site.py http://localhost:8800/   # 쪽 링크와 정적 자원(아이콘, 폰트) 응답
```

### 4-3. 검수 문서 작성 규칙

- 원고에 옮길 문장은 "교체" 코드 상자에만 둡니다. "현재" 상자는 원고 문장을 줄이지 않고 그대로 적습니다.
- **수정안 시험 적용:** 모든 교체 문장을 작업 사본에 적용한 뒤 빌드, 금칙어, lint, verify_site를 실행하고 출력 원문을 문서 1절에 넣었습니다. "현재" 문장이 원본에서 정확히 1건씩 일치하는지도 스크립트로 확인했습니다.
- **실패 시험:** 검사 보강을 지시했을 때는 일부러 결함을 넣은 사본에서 검사가 실패하는 출력까지 확인했습니다.
- 사실은 원문(공식 문서, 발표 글)으로 확인하고 확인한 위치를 이유 칸에 적습니다. 확인하지 못한 것은 "미확인"으로 미결정에 둡니다.
- 작가 경험과 의견은 지어내지 않습니다. 결정이 필요한 것은 선택지와 권장안으로 미결정에 둡니다.
- 사용자 표기 선호: 나열은 가운뎃점 대신 쉼표, 답변 끝에 미결정 목록, 명령은 첫 단계부터 한 덩어리로, sleep은 5초 이하

### 4-4. 반복해서 겪은 문제와 대처

| 문제 | 대처 |
|---|---|
| 배포 사이트가 컨테이너에서 403 | 로컬 서버로 빌드 결과를 띄워 확인. 조회 도구(web_fetch)의 결과는 캐시일 수 있음(1장 옛 원고가 보였던 일이 캐시였음) |
| 비교 도서(위키독스 19712, 19689) 직접 접근 403 | 웹 검색 결과에 나온 링크로 다시 받으면 전체 목차를 받을 수 있음 |
| 참고 자료 링크 글자가 늘면 100자 초과 경고 | 시험 적용으로 미리 찾아 문장을 나눔 |
| nav에서 표지를 빼면 표지가 빌드되지 않음 | build.py의 ORDER를 함께 수정(이미 반영) |
| 작가 결정과 저장소 결정 기록이 다른 경우(D-042, D-044) | 한 번만 표로 제시하고 작가 선택을 받음 |
| 작성 쪽이 검수 문서를 등록하지 않거나 일부 항목을 빠뜨림 | 반영 확인 때 교체 문장이 원고에 있는지 스크립트로 대조(예: "반영 37 / 37") |

## 5. 사실 확인에서 바로잡은 것 (재발 주의)

- Claude Code 권한 모드 기본값: v2.1.283 이상은 대화형 터미널과 VS Code 세션이 모든 요금제에서 auto 모드로 시작(요금제별로 다르다는 설명은 이전 내용)
- Codex 승인 정책 untrusted는 폐지(0.149). push 금지는 승인 정책만으로는 강제되지 않고 Rules(prefix_rule, decision forbidden)로 강제. Rules는 실험 단계
- Claude Code는 CLAUDE.md가 없으면 AGENTS.md를 읽음
- /usage의 Session 항목은 API 사용자용이며 금액은 정가 기준이라 청구액과 다를 수 있음
- OpenAI 하네스 엔지니어링 글의 사례는 "Codex 팀"이 아니라 Codex로 제품을 개발한 OpenAI 팀
