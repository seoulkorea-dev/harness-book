# 하네스 책 구조 진단과 개편안

- 작성일: 2026-10-15
- 작성: 검수 채팅(Claude)
- 기준 커밋: 915da5f
- 성격: 사용자 결정 전 제안 문서. 결정 뒤 누적 4차 검수 문서로 개편 지시를 작성합니다.

전체 원고와 결정 기록 D-051~D-060을 확인했습니다. 지적하신 문제는 원고에서 그대로 확인됩니다. 다만 해결하려면 기존 결정 두 건(D-032 목차 확정, D-052 하네스 정의 유지)을 바꿔야 합니다. 그래서 진단과 개편안을 먼저 정리하고, 결정을 받은 뒤 검수 문서를 작성합니다.

## 1. 진단

### ① 하네스가 책의 중심이 아님

- 1장 제목이 "모델, 프롬프트, 컨텍스트, 하네스의 관계"이고, 하네스는 세 층 가운데 세 번째로 소개됩니다.
- 정의도 "모델 바깥에서 에이전트가 일하는 환경을 이루는 장치 전체" 한 문장뿐이라, 하네스가 실제로 무엇을 하는지 드러나지 않습니다.
- 독자는 2장(프롬프트)과 3장(컨텍스트)을 먼저 읽고, 하네스의 구성 요소는 4장에 가서야 만납니다.

### ② 에이전트와 하네스의 관계가 정의되지 않음

- 에이전트 정의는 1장의 한 문장("모델이 반복 루프 안에서 스스로 도구를 사용하는 시스템")뿐이고, 그 루프를 누가 돌리는지에 대한 설명이 없습니다.
- Claude Code 공식 용어집(code.claude.com/docs/en/glossary, "Agentic harness" 항목)은 관계를 분명히 밝힙니다. 하네스는 언어 모델을 코딩 에이전트로 만드는 도구, 컨텍스트 관리, 실행 환경입니다. Claude Code가 하네스이고 Claude는 그 안의 모델입니다. 하네스는 파일 접근, 셸 실행, 권한 확인, 메모리 로딩, 행동을 이어 가는 루프를 제공합니다.
- 원고는 D-052에 따라 이 정의를 "차이"로만 소개하고, 컨텍스트를 하네스 밖의 별도 층으로 둡니다. 그래서 독자는 "에이전트 = 모델 + 하네스"라는 핵심 관계를 얻지 못합니다.

### ③ 하네스로 에이전트를 설계하는 장이 없음

- 설계에 필요한 재료는 흩어져 있습니다: 1장 표 1-2, 4장 구성 요소와 에이전트 루프, 4장 주간 보고서 구현, examples/ch01-01.
- "이 업무를 맡을 에이전트를 처음부터 설계한다"는 흐름의 장은 없습니다.

### ④ 진행 방식에 대한 관찰

- D-053~D-060의 원고 보강 8건(새 절 7개, 그림 10개)이 2026-10-15 08:42~09:00 UTC 사이에 커밋되었고, 아직 검수 문서를 거치지 않았습니다.
- 검수 AI 인계 지침은 작성 A가 검수 문서 없이 큰 구조 변경을 하지 않도록 정합니다. 이번 개편도 결정을 먼저 정한 뒤 검수 문서 단위로 진행할 것을 권합니다.

## 2. 개편안 (권장)

### 2-1. 정의 초안 (작가 승인 필요, 근거: Claude Code 용어집)

| 용어 | 정의 초안 |
|---|---|
| 에이전트 | 모델이 도구를 사용해 작업하고, 결과를 확인하며, 목표를 이룰 때까지 반복하는 시스템입니다. 에이전트는 모델과 하네스로 이루어집니다. |
| 하네스 | 모델을 에이전트로 동작하게 하는, 모델 바깥의 실행 장치 전체입니다. 루프를 실행하고, 도구를 제공하고, 모델에 넘길 컨텍스트를 관리하며, 권한, 기록, 검증으로 작업 범위와 결과를 통제합니다. |
| 관계를 보여 주는 문장 | 같은 모델이 채팅 화면에서는 답변만 하고, Claude Code 안에서는 파일 수정과 테스트까지 수행합니다. 차이를 만드는 것은 하네스입니다. |
| 프롬프트와 컨텍스트의 위치 | 프롬프트는 사람이 하네스에 넣는 요청이고, 컨텍스트는 하네스가 루프마다 모델에 넘기는 정보입니다. 둘 다 하네스 안의 설계 대상입니다. |

### 2-2. 목차 재배치 (기존 원고를 최대한 옮겨 쓰는 방식)

| 새 순서 | 내용 | 원고 출처 |
|---|---|---|
| 1장 하네스란 무엇인가 | 에이전트 = 모델 + 하네스, 에이전트 루프, 하네스가 하는 일 | 1장 일부, 4장 에이전트 루프 절 |
| 2장 하네스의 구성 요소 | 역할, 도구, 권한, 기록, 검증, 도구 노출 범위, 지시와 강제 | 4장 |
| 3장 하네스로 에이전트 설계하기(신규) | 에이전트 명세서(목적, 역할, 입력, 도구, 권한, 기록, 검증, 종료 조건, 승인 지점), 주간 보고서 에이전트를 처음부터 설계, 제품 파일(CLAUDE.md, settings.json 등)로 옮기기 | 1장 예제, 4장 구현 절, examples/ch01-01 |
| 4장 요청 설계(프롬프트) | 하네스에 넣는 요청 | 2장 |
| 5장 정보 설계(컨텍스트) | 하네스가 모델에 넘기는 정보 | 3장 |
| 6~9장 운영 | 착수, 검증, 기록과 인계, 위험 관리 | 5~8장 |
| 10장, 11장 | 제품 비교, 작가 사례 | 9장, 10장 |

- 이 안을 택하면 시작하며, 표지, 용어 풀이의 "세 설계 층" 표현도 함께 바뀝니다.

## 3. 배경 밝기 2단계

D-051로 이미 한 번 밝아진 상태(`--paper #FCFCFA`)에서 2단계를 더 올린 값을 제안합니다.

| 변수 | 현재 | 1단계 | 2단계(제안) |
|---|---|---|---|
| --paper | #FCFCFA | #FDFDFC | #FFFFFF |
| --panel | #F2F2EE | #F5F5F2 | #F8F8F6 |
| --rule | #E2E2DC | #E6E6E1 | #EAEAE6 |

함께 고칠 곳:

- 그림 안 바탕: 크림색 `#FAF6EB` 37곳, `#F3EDDF` 2곳이 남아 있습니다(D-051 때 그림은 바꾸지 않음). 흰 바탕 위에 누런 상자가 보이므로 각각 `#F8F8F6`, `#F2F2EE`로 맞춥니다.
- 코드 상자: `assets/style.css`의 고정값 `#fffdf6`도 함께 정리합니다.

대비:

- 본문색 #2B2A26은 흰 바탕에서 대비가 오히려 좋아집니다.
- 링크색 #0284c7은 흰 바탕에서 4.10:1로, D-020에서 이미 감수하기로 한 수준과 같습니다.
